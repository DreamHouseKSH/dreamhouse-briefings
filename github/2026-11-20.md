### [firecrawl/firecrawl](https://github.com/firecrawl/firecrawl)

 ⭐ 204,083 · 📈 +795 일간 · ⚖️ AGPL-3.0 · 🗓️ 생성 2024-04-15 

![firecrawl/firecrawl 대표 이미지](https://opengraph.githubassets.com/1/firecrawl/firecrawl){: .gh-img loading="lazy"}

웹사이트를 깨끗한 마크다운으로 — 검색·스크레이프·550개 이상 데이터 제공사를 하나의 API로.
{: .gh-lead}

**무엇인가** — "에이전트를 똑똑하게 만드는 지식 인프라"를 표방하는 웹 데이터 도구. 사이트를 스크레이프·크롤해 LLM이 바로 쓰는 마크다운으로 바꿔준다. 세 가지 경로가 있다: 내 컴퓨터에서 단일 바이너리로 돌리는 Firecrawl Local(MCP 서버로 에이전트에 직결), 호스티드 Firecrawl Cloud(firecrawl.dev, 검색과 'Alexandria' 550여 데이터 제공사 포함), 그리고 큐·워커·DB까지 올리는 전체 셀프호스트다. 누적 별 20.4만 개의 대형 프로젝트다.

**왜 지금 뜨나** — 관측 일간 +795로 첫 등장. 스킬·하네스 부류의 나흘 연속 강세 속에 '에이전트가 읽을 데이터를 공급하는' 축의 대표로 읽힌다. `init` 한 번으로 Claude Code·Cursor·Codex 등에 MCP 서버로 붙는 설계라 스킬 생태계와 직접 맞물린다. 직접적인 촉발 이벤트는 확인되지 않았다.

**어떻게 쓰나** — `cargo install firecrawl-local`(Rust 필요) 또는 클라우드의 `npx firecrawl-cli scrape <url>`로 시작한다. `firecrawl-local init`이 로컬의 AI 도구들을 찾아 MCP 서버로 등록하고, `serve`는 로컬호스트 3002번에 v2 API를 띄운다.

**비슷한 도구와 비교** — 같은 날 목록의 CLI-Anything이 '소프트웨어를 에이전트용으로 번역'한다면, firecrawl은 '웹을 에이전트용으로 번역'한다. 둘 다 에이전트의 입력 면을 넓히는 부류다.

**주의할 점** — 기본 설정에서 로컬 스크레이프가 안 되는 페이지는 Firecrawl Cloud가 대신 가져오며 결과에 표시된다. 완전 로컬을 원하면 `FIRECRAWL_CLOUD=off`로 끊어야 한다. AGPL-3.0이라 사내 서비스 통합 시 라이선스 검토가 필요하다. 열린 이슈 839건(관측 시점). 실행 시험은 하지 않았다.
{: .gh-warn}
