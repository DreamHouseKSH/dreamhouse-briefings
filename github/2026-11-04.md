**비슷한 도구와 비교** — T3 Code가 코딩 에이전트의 작업을 묶는 화면이라면 이 도구는 일반 데스크톱 앱의 조작 수단이다. 브라우저 페이지에만 필요한 작업과 운영체제 앱 조작을 구분해 선택해야 하며, 화면 좌표 방식과의 성공률 비교는 미실시다.

병렬 에이전트에게 각각의 작업 폴더를 주고 전환을 단순하게 만든다.
{: .gh-lead}

**무엇인가** — Git worktree(같은 저장소에서 서로 다른 브랜치를 별도 작업 폴더로 여는 기능)를 관리하는 명령행 도구다. 브랜치 이름으로 폴더를 전환·생성·정리하고, 작업 단계에 연결한 명령으로 반복 절차를 자동화한다.

**왜 지금 뜨나** — 전체·Rust 일간 +438, 전체 주간 +749를 확인했다. 전일 일간 표시 +136보다 커졌지만 별 증가 원인은 확인되지 않았다. 최신 정식 버전 v0.81.0은 대화형 작업 명령과 다른 작업 폴더의 브랜치를 병합하는 기능을 담는다.

**어떻게 쓰나** — 공식 설치 경로를 고르고 셸 연동을 설정한 뒤 `wt list`로 상태를 본다. `wt switch`로 대상 작업 폴더를 선택하는 흐름이다. Windows에서는 기존 Windows Terminal의 `wt` 이름과 충돌할 수 있어 `git-wt` 경로를 안내한다.

**비슷한 도구와 비교** — 기본 `git worktree`만으로도 작업 폴더 분리는 가능하다. Worktrunk는 그 위에 이름 기반 이동과 편의 자동화를 얹으며, T3 Code의 통합 대화 화면과는 서로 다른 문제를 다룬다. 자동화가 필요 없으면 기본 Git만 쓰는 선택도 합리적이다.

**주의할 점** — 0.x 릴리스의 호환성 변경과 병합·삭제 동작을 먼저 확인해야 한다. 연결 명령은 저장소 코드를 실행할 수 있으므로 신뢰하지 않는 설정을 자동 승인하지 않는다. GitHub API(Application Programming Interface, 프로그램끼리 데이터를 주고받는 창구)는 라이선스를 Other로 분류했지만 실제 LICENSE는 MIT 또는 Apache-2.0 선택형이다. 별 수가 작업 충돌 방지를 보장하지 않는다.
{: .gh-warn}

취약점 후보를 찾는 단계와 반증·검증하는 단계를 분리한다.
{: .gh-lead}

**무엇인가** — 코딩 에이전트가 저장소의 구조·신뢰 경계를 조사하고 보안 문제 후보를 찾은 뒤 별도 에이전트가 검증하도록 하는 작업 지침 모음이다. 조사 범위 장부와 구조화된 결과, 독립적인 근거 확인을 통해 보고서를 만든다. 취약점 탐지 모델 자체를 배포하는 저장소는 아니다.

**왜 지금 뜨나** — 전체 주간 +8,598을 확인해 주간 보완 카드로 선정했다. 이번에 조회한 일간 목록들에서는 증가량을 확인하지 못했다. README는 Cloudflare의 취약점 발견 체계의 출발점이 된 단일 저장소용 지침이라고 설명한다. 정식 릴리스 조회는 404였고 특정 새 버전이 인기 원인이라고 말할 수 없다.

**어떻게 쓰나** — 도구 사용과 병렬 작업을 지원하는 코딩 에이전트에 지침을 설치하고 권한이 있는 저장소의 감사 범위를 지정한다. 검증용 프로그램 실행에는 운영체제로 강제한 격리, 외부 통신 차단, 정리된 환경 변수와 자원 제한이 필요하다고 README가 명시한다. 조건이 없으면 미검증 상태로 남기는 흐름이다.

**비슷한 도구와 비교** — 단순 보안 체크리스트와 달리 후보 발견자와 검증자를 분리하고, 확인됨·추가 검증 필요·기각을 구별한다. 기존 정적 분석이나 사람의 보안 검토를 대체한다고 확인한 것은 아니다. 탐지 개수보다 근거 추적과 재현 가능성을 평가할 필요가 있다.

**주의할 점** — 2026년 6월 생성, MIT 라이선스이고 정식 릴리스는 확인되지 않았다. 프로젝트는 한 번의 실행보다 반복 조사가 더 많은 문제를 찾았다고 자체 설명하지만 이번 조사에서 재현하지 않았다. 신뢰하지 않는 코드를 실행하는 감사 자체에도 위험이 있다. 허가된 대상만 다루고 높은 별 수를 취약점 정확도나 안전성 보증으로 쓰지 않는다.

## 확인 범위와 남은 공백

- [전체 일간](https://github.com/trending?since=daily)·[전체 주간](https://github.com/trending?since=weekly)과 Python·TypeScript·Rust 일간만 조사했다. 모든 언어·저장소의 순위표가 아니다. 목록 화면은 원문에서 직접 새로 조회했고, 오래된 검색 색인 수치를 오늘 값으로 쓰지 않았다.
- 선정 9개 모두 메타데이터·README·LICENSE를 직접 읽고 최신 정식 릴리스를 조회했다. Spotify Portal과 Cloudflare 저장소는 최신 정식 릴리스 조회가 404여서 태그·배포판이 전혀 없다고 확대 해석하지 않았다. Worktrunk는 메타데이터가 Other로 분류하지만 실제 LICENSE와 README는 MIT 또는 Apache-2.0 선택형이다.
- README의 현재 기본 브랜치와 최신 정식 릴리스 내용은 다를 수 있다. 기능 소개는 조회한 README, 버전 배지는 정식 릴리스 기준이다. 설치·성능 측정·별 계정 감사는 하지 않았으며 별 증가를 실사용·안전성·품질 지표로 바꾸지 않는다.
- HN(Hacker News, 개발자 커뮤니티)에서 각 저장소 주소를 검색했다. 과거 게시물도 섞이므로 검색 결과를 오늘 반응이나 상승 원인의 증거로 사용하지 않았다. X·Reddit 의견은 별도로 검증하지 않았다.
