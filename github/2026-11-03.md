![max-sixty/worktrunk 프로젝트 소개](https://cdn.jsdelivr.net/gh/max-sixty/worktrunk-assets@main/assets/docs/light/wt-core.gif){: .gh-img loading="lazy"}

> 출처: [프로젝트 원문](https://github.com/max-sixty/worktrunk) — 원본 이미지 핫링크, 복제 저장 아님.

병렬 에이전트에게 각각의 작업 폴더를 주고 전환을 단순하게 만든다.
{: .gh-lead}

**무엇인가** — Git worktree(같은 저장소에서 서로 다른 브랜치를 별도 작업 폴더로 여는 기능)를 관리하는 명령행 도구다. 브랜치 이름으로 폴더를 전환·생성·정리하고, 작업 단계에 연결한 명령으로 반복 절차를 자동화한다.

**왜 지금 뜨나** — Rust 일간에서 +136을 확인했다. 가장 큰 증가량의 프로젝트는 아니지만 병렬 코딩 작업의 실무 문제를 보여 주는 카드로 선정했다. v0.81.0에는 대화형 확인이 가능한 작업 명령과 다른 작업 폴더의 브랜치를 병합하는 기능 변화가 있다.

**어떻게 쓰나** — 공식 설치 경로를 고르고 셸 연동을 설정한 뒤 `wt list`로 상태를 본다. `wt switch`로 대상 작업 폴더를 선택하는 흐름이다. Windows에서는 기존 Windows Terminal의 `wt` 이름과 충돌할 수 있어 `git-wt` 경로를 안내한다.

**비슷한 도구와 비교** — 기본 `git worktree`만으로도 작업 폴더 분리는 가능하다. Worktrunk는 그 위에 이름 기반 이동과 편의 자동화를 얹으며, T3 Code의 통합 대화 화면과는 서로 다른 문제를 다룬다. 자동화가 필요 없으면 기본 Git만 쓰는 선택도 합리적이다.

**주의할 점** — 0.x 릴리스의 호환성 변경과 병합·삭제 동작을 먼저 확인해야 한다. 연결 명령은 저장소 코드를 실행할 수 있으므로 신뢰하지 않는 설정을 자동 승인하지 않는다. GitHub API는 라이선스를 Other로 분류했지만 실제 LICENSE는 MIT 또는 Apache-2.0 선택형이다. 별 수가 작업 충돌 방지를 보장하지 않는다.
{: .gh-warn}

**왜 지금 뜨나** — 일간 +1,799, 주간 +5,852가 확인됐다. 새 v15.9.0은 Devin 연결, 원격 작업자 주소 설정, 비밀값 가림 확대와 오류 보고 비활성화 시 대기 중 전송 중단을 포함한다. 어제 카드의 v15.8.1 이후 보안·운영 변화가 실제로 있었다.
