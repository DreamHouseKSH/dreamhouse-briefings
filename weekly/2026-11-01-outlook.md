# 주간 전망 — 2026-11-01

> 대상 기간은 2026-11-02(월)~11-06(금), KST(Korea Standard Time, 한국 표준시)입니다. 실제 작성·게시일은 11월 1일입니다. 직전 10/26~30 뉴스 20파일·44항목과 GitHub 5파일·45카드(22개 고유 저장소), 최근 주간 보고를 읽었습니다. **10/26 모델, 10/26~28·30 X 파일은 없으며**, 10/27에는 다음 날 사후 보충한 4항목이 포함됩니다. 아침판 이후의 사건 전체를 망라하지 않습니다. 핵심 발표·일정은 공식 원문으로 재확인했고, 아래 전망은 편집적 해석입니다. 실제 기기 시험·독립 성능 평가·개별 운영환경 점검은 하지 않았으며 가격 예측이나 투자 권유를 다루지 않습니다.

## 이번 전망의 출발점 — 기다릴 것과 이미 바뀐 것을 나눈다

지난주 아카이브의 공통 질문은 AI(Artificial Intelligence, 인공지능)가 얼마나 많은 일을 말할 수 있는가보다, 어떤 조건에서 실제 일을 수행하는가였다. 기업 업무에 연결하는 에이전트(agent, 목표에 맞춰 도구로 여러 단계의 일을 수행하는 프로그램), 음성을 직접 다루는 작은 모델, 생성된 코드와 화면을 검사하는 도구가 함께 나타났다. 다음 주에도 이 흐름을 관찰하되, 새 이름이 나올 것이라는 예측 대신 **현재 제공 범위와 실행 결과 사이의 간격**을 확인하려 한다.

이미 달라진 조건부터 반영해야 한다. 10/28 뉴스와 토요일 리뷰에서 다룬 Ollama v0.40.12의 LFM3 지원은 그 버전에 한해 Apple 하드웨어로 제한됐다. 그러나 공식 [v0.40.13](https://github.com/ollama/ollama/releases/tag/v0.40.13)은 Linux·Windows로 지원이 넓어졌다고 명시한다. 공개 시각은 10/29 04:55 KST다. 이것을 앞으로 나올 소식으로 남겨두면 오래된 제약을 전망의 전제로 삼게 된다. 이번 전망은 과거 버전 설명을 현재 제품 전체의 제한으로 재사용하지 않는다.

반대로 아직 계획인 것은 계획으로 둔다. 다음 주에는 AMD·Qualcomm·Arm의 공식 실적 설명회와 Apple M6 제품의 한국 출시일이 잡혀 있지만, 발표될 수치·실제 제품 평가·추가 모델 출시 날짜까지 확정된 것은 아니다. 일정이 있다는 사실과 결과를 안다는 것은 다르다.

## 분야별 조건부 전망

### IT — 반도체의 수요를 사용처와 비용으로 나누어 본다

IT(Information Technology, 정보기술) 분야의 관찰 출발점은 사업별 차이다. [삼성전자 10월 29일 공식 실적](https://news.samsung.com/global/samsung-electronics-announces-third-quarter-2026-results)은 반도체 사업의 강한 실적과 모바일·가전 등을 담당하는 DX(Device eXperience, 사용자 기기 사업 부문)의 영업손실을 함께 보고했다. 회사는 메모리의 수요와 공급 제약을 설명하는 동시에 완제품 사업의 비용 부담도 제시했다. 같은 산업 안에서도 부품을 파는 쪽과 사는 쪽의 경제적 조건이 다를 수 있다는 출발점이다. 이번 전망은 지난 실적의 큰 숫자를 되풀이하거나 세 회사의 서로 다른 회계 기간을 단일 순위로 묶지 않는다.

다음 주 실적 설명회는 수요가 모두 입증되는 날이 아니라, 기업별 공급·비용·사용처를 나누어 확인할 기회다. **조건부 관찰:** AMD·Qualcomm·Arm이 새 자료를 공개하면 데이터센터·개인용 기기 등 적용처의 설명, 이미 발생한 매출과 앞으로의 전망, 제품 공급과 고객 채택을 구분해 읽을 것이다. 구체적 물량이나 고객 사용 결과가 나오면 막연한 성장 설명을 좁힐 수 있다. 반면 장기 계획만 반복된다면 실현 여부는 미확인으로 남는다. 콜에서 특정 질문이 반드시 답변된다고 예고하지 않는다.

소비자 장치 쪽에서는 [Apple 한국 MacBook Pro 발표](https://www.apple.com/kr/newsroom/2026/10/apple-introduces-the-new-14-inch-macbook-pro-with-m6/)와 [iMac 발표](https://www.apple.com/kr/newsroom/2026/10/apple-unveils-new-imac-with-m6/)가 모두 11월 6일 출시를 안내한다. 미국 예약 주문일을 한국 일정으로 옮기지 않고 한국 원문을 따랐다. **조건부 관찰:** 출시 뒤 실제 사용 보고가 나온다면 동일한 앱·모델·메모리 구성·작업 길이에서 비교했는지 확인할 필요가 있다. 회사의 최대 향상률과 한 사용자의 체감, 장시간 작업의 지속 성능은 다른 증거다. 이번 글은 구매나 교체를 권하지 않으며 아직 없는 독립 시험 결과를 대신 만들지 않는다.

### AI — 업무 통합의 가치는 승인과 예외 처리에서 드러난다

[OpenAI–ServiceNow 공식 발표](https://openai.com/index/openai-servicenow-partnership-expansion/)는 현재 제공하는 MCP(Model Context Protocol, AI가 외부 도구·데이터에 연결하는 규약) 플러그인(plugin, 기존 제품에 기능을 덧붙이는 확장 묶음)과 이후 통합 계획을 구분한다. 고객이 연결할 기능을 선택하고 기존 업무 규칙과 권한을 적용한다는 설명이다. 음성 기능은 2027년 1분기, 보안 기능은 1월 초기 접근과 2분기 일반 제공, Codex 통합은 2027년 계획으로 남아 있다.

2027년으로 예고된 통합을 다음 주 출시 기대에 섞으면, 현재 이용 가능한 기능을 오히려 잘못 보게 된다. **조건부 관찰:** 다음 주 고객 사례나 제품 문서가 보강된다면, 단순한 연결 성공보다 누가 어떤 변경을 승인하는지, 실패 뒤 중복 실행을 어떻게 막는지, 사람이 다시 맡는 예외가 얼마나 남는지를 읽어야 한다. 이 기준은 회사가 그런 문제를 이미 해결했다는 결론이 아니라 실제 업무 적용을 평가하기 위한 편집적 질문이다.

10/27~30 아카이브의 Oracle·Fragment·Serval 소식도 기업 업무를 실행 가능한 절차로 바꾸려는 방향에서 연결된다. 하지만 투자 유치, 신제품 발표, 실제 고객 성과를 같은 단계로 보지 않는다. 이번 전망은 이 회사들의 비용 절감이나 오류율을 새로 입증하지 않았으므로 공통 수치를 만들지 않는다. 다음 주 구체적인 실행 기록이 나오지 않는다면 “도입 성과 확인 전”이라는 상태가 유지되는 것이 더 정확하다.

### 모델 — 공개 파일보다 작업 적합성과 이용 조건을 본다

[Liquid AI의 LFM3 공식 설명](https://www.liquid.ai/blog/lfm3)은 텍스트·시각·음성·복합 입력·판단용 소형 모델들을 소개한다. 동시에 코딩과 지식 과제에서는 더 큰 모델이 앞서는 영역도 인정한다. 따라서 작은 모델의 등장만으로 범용 대형 모델을 일괄 대체한다고 전망할 근거는 없다. **조건부 관찰:** 새로운 적용 사례가 나온다면 모델을 바꾼 목적, 다루는 언어와 입력 길이, 틀린 결과를 가려내는 기준이 함께 공개되는지를 보자. 특정 업무에서 빠르게 실행된다는 결과는 다른 언어·긴 자료에서의 정확도를 보장하지 않는다.

[Mistral Large 4 공식 발표](https://mistral.ai/news/mistral-large-4-oss/)는 개선판 공개 가중치(Open weights, 학습된 모델의 수치 파일을 내려받을 수 있는 배포 방식)와 자체 배포 경로를 설명한다. 그러나 Model-as-a-Service(외부 이용자에게 모델을 서비스로 제공하는 사업) 사업자의 상업 이용에는 별도 라이선스를 요구한다고 명시한다. 이번 확인은 발표 본문에 적힌 조건을 재확인한 것이며 법률 자문이나 개별 사업의 허용 여부 판정이 아니다.

**조건부 관찰:** 다음 주의 의미 있는 후속 정보는 새로운 종합 순위뿐 아니라, 공개된 개선판과 실제 배포 파일이 같은지, 사용한 추론 엔진(inference engine, 모델을 불러 결과를 계산하는 실행 소프트웨어)과 설정이 무엇인지, 이용허락 조건에 맞는 경로인지까지 설명하는 자료다. 이런 조건이 없다면 빠른 시연만으로 운영 준비가 끝났다고 판단하기 어렵다. 개발사 자체 성능 수치는 독립적으로 재현된 결과와 계속 구분한다.

### 엔진 — 지원 확대 다음에는 음성 왕복과 실패 동작을 확인한다

Ollama의 운영체제 지원 확대는 이미 확인됐으므로, 다음 질문은 출시를 기다리는 일이 아니라 실제 장치와 작업에서의 재현성이다. [v0.40.13 공식 기록](https://github.com/ollama/ollama/releases/tag/v0.40.13)은 LFM3 계열과 음성 합성 경로가 Linux·Windows에서도 작동한다고 설명하지만, 이 문서만으로 모든 장치의 처리 속도·메모리 사용·언어별 품질이 같아지는 것은 아니다. 이번 브리핑은 직접 설치하거나 측정하지 않았다.

[llama.cpp v0.8.0](https://github.com/ggml-org/llama.cpp/releases/tag/v0.8.0)도 LFM3와 실시간 음성 입력·출력 경로를 포함하지만, 스트리밍 음성 API(Application Programming Interface, 프로그램끼리 기능·데이터를 주고받는 접점)는 실험적이라고 표시한다. API와 실행 옵션의 변경 역시 기존 응용 프로그램에서 별도 확인할 조건이다. 두 엔진의 지원 발표를 하나의 동일한 실행환경으로 합치지 않는다.

**조건부 관찰:** 다음 주 재현 자료를 읽을 때에는 첫 응답 속도뿐 아니라 긴 음성의 누락, 중단 후 재개, 도구 호출 실패 뒤의 처리, 같은 입력을 반복했을 때 결과가 유지되는지를 살피는 편이 유용하다. 새 릴리스가 나오면 정확한 버전과 변경 항목을 기록하고, 나오지 않으면 현재 문서의 미확인 범위를 유지한다. “곧 지원”이라는 오래된 문구를 반복하는 것과 “모든 환경에서 완성”이라고 뛰어넘는 것 모두 피해야 한다.

### GitHub — 관심의 크기보다 검사의 범위와 빠진 부분을 읽는다

지난주 45카드 가운데 반복 수록된 도구들은 생성 자체뿐 아니라 검토와 작업 관리에 초점을 두고 있었다. 다만 이는 이 브리핑이 고른 표본이다. GitHub 전체의 도입률이나 생산성 향상을 측정한 것이 아니며, 별 수를 합쳐 다음 주 인기 순위를 예상하지 않는다.

[Cloudflare 감사 스킬의 현재 설명](https://github.com/cloudflare/security-audit-skill/blob/main/README.md)은 확인된 결과·추가 검증 필요·기각을 나누며 근거와 검사 범위를 기록한다. [NVIDIA SkillSpector](https://github.com/NVIDIA/SkillSpector/blob/main/README.md)는 설치 전 스킬(skill, 반복 업무용 지침과 도구 묶음)을 검사하지만, 검사 대상 코드를 실행하거나 호스트를 샌드박스(sandbox, 실행의 영향을 격리하는 공간)로 만드는 도구가 아니라고 명시한다. 현재 문서의 재확인이지 모든 기능이 지난주 새로 생겼다는 주장은 아니다.

**조건부 관찰:** 다음 주에는 발견 건수가 늘었는지보다 검사하지 못한 부분이 표시되는지, 어떤 근거로 결론을 내렸는지, 실제 수정 뒤 같은 조건으로 다시 확인했는지를 보자. 특히 검사 통과를 실행 권한의 확대나 모든 위험 제거로 바꾸어 읽으면 안 된다. 도구가 한계를 더 분명하게 보고하는 것은 결과 개수가 적더라도 유용한 진전일 수 있다.

## 공식 일정 — 날짜와 시각이 확인된 관찰 창

아래 질문은 결과 예측이 아니라 발표 뒤 읽을 기준이다. 미국 기업 세 곳의 **정확한 시각은 실적 자료 게시 시각이 아니라 설명회 시작 시각**이다. 실적 자료는 각 원문이 “미국 장 마감 후”로만 안내한다. 회계연도는 회사가 실적을 집계하는 기간이며 달력연도와 다를 수 있다.

[NIST의 공식 시간 안내](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst)에 따르면 미국의 일광절약시간은 11월 1일 현지 02시에 끝난다. 따라서 위 설명회는 미국 동부에 14시간, 태평양에 17시간을 더해 한국시간으로 환산했다. AMD의 일반 행사 목록에 남아 있는 일광시간 표기 대신 날짜별 보도자료의 동부·태평양시간과 이 전환 규칙을 적용했다. 일광절약시간(Daylight Saving Time, 계절에 따라 시계를 앞당겨 쓰는 제도)을 지난주처럼 적용하면 한 시간 어긋난다.

일정은 작성 시점 공식 공지 기준이며 변경될 수 있다. Apple 출시 날짜는 정확한 판매 개시 시각이나 모든 구성의 배송 보장이 아니다. 월·화·금에 다른 행사가 전혀 없다는 뜻도 아니며, 이 표는 직접 확인한 관련 일정만 담았다.

## 전문가 전망과 검증 한계

이번 작성에서 다음 주의 특정 사건·날짜에 연결해 직접 원문을 확인한 독립 전문가 전망은 확보하지 못했다. 따라서 기업 경영진의 홍보 문구나 파트너 추천을 전문가들의 합의처럼 소개하지 않는다. 위 조건부 전망은 편집자의 질문과 해석이며, 회사·개발자의 문서는 발표·지원 범위·알려진 제한을 확인하는 자료로 사용했다.

자료의 범위도 고정돼 있지 않다. 지난주 GitHub 조사에는 월~목 Rust·Go 목록이 포함됐고 금요일은 TypeScript 목록을 포함했다. TOP 5 역시 월~수에는 확인 목록의 합집합, 목~금에는 상세 카드 선별 목록을 기준으로 했다. 이러한 표본을 같은 모집단의 연속 순위로 연결하거나 현재 누적 별로 과거 하루 증가를 복원하지 않는다.

10/27 뉴스 4항목의 사후 보충, 일부 원문의 게시 시각 미공개, X 직접 원문 접근 한계도 남는다. 이번에는 핵심 주장과 일정의 공식 출처를 다시 읽었지만 과거 기사 모든 문장·모든 숫자를 재감사한 것은 아니다. 아카이브에 빠진 분야가 전 세계에서 조용했다는 뜻으로 공백을 채우지 않는다.
