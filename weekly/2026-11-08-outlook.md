# 주간 전망 — 2026-11-08

> 전망 대상은 2026-11-09(월)~11-13(금), KST(Korea Standard Time, 한국 표준시)이며 실제 작성·게시일은 11월 8일입니다. 직전 월~금 뉴스 19파일·38항목과 GitHub 3파일·25카드(17개 고유 저장소), 최근 주간 보고를 읽고 토요일 뉴스 3파일·4항목을 별도 보완했습니다. **11/5·6 GitHub, 11/2·4·7 모델, 11/2·3·5·6·7 X 파일은 없습니다.** 주말 GitHub는 정규 발행 대상이 아닙니다. 11/6 뉴스에는 17:00 사후 보충 7항목이 있으며 정규 마감은 08:01로 유지됐습니다. 토요일 4항목 중 3항목도 원문 날짜만 확인된 참고 보충입니다. 아침판 이후 모든 사건의 전수 조사나 모든 항목의 최초 시각 검증을 뜻하지 않습니다. 아래의 공식 일정·현재 문서·조건부 해석을 구분했으며 설치·계정별 이용·독립 성능 시험은 하지 않았습니다. 투자 매매 권유나 가격 전망은 다루지 않습니다.

## 이번 전망의 출발점 — 달력과 판단 기준을 나눈다

[토요일 주간 정리](2026-11-07-review.md)의 질문은 ‘무엇을 더 할 수 있는가’와 ‘어떤 조건에서 믿을 수 있는가’를 함께 읽자는 것이었다. 다음 주에는 그 조건을 확인할 자리가 있다. NVIDIA AI Day Seoul, KubeCon + CloudNativeCon North America, IBM Quantum Developer Conference, Cisco 실적 설명회는 각각 현장 적용, 공동 운영 기반, 연구 결과, 사업 성과라는 다른 종류의 자료를 내놓을 수 있다. 다만 행사 날짜가 확정됐다는 사실은 특정 신제품이나 성능 개선이 그날 발표된다는 보장이 아니다.

이 글은 두 층으로 나눈다. 공식 일정은 주최자가 밝힌 날짜·시간·접근 조건을 적는다. 분야별 전망은 자료가 실제로 나왔을 때 무엇을 확인할지 정한 편집적 해석이다. 회의가 끝나도 녹화나 논문이 바로 공개되지 않을 수 있고, 제품 문서가 바뀌어도 모든 계정에 같은 기능이 적용됐다고 단정할 수 없다. 새로운 증거가 없으면 확인하지 못한 상태를 그대로 남기는 것이 이번 전망의 원칙이다.

주중 기록의 빈칸도 출발점에 포함한다. GitHub는 월~수만 있으므로 최근 별 증가나 인기 순위로 목·금의 관찰을 대신 만들지 않았다. 토요일 뉴스와 일요일 아침 확인한 공개 릴리스는 후속 정보로 따로 다룬다. 과거에 읽은 설명을 현재 상태로 반복하지 않는 것이 전망에 앞선 첫 점검이다.

## 분야별 조건부 전망

### IT — 반도체의 성장에서 네트워크와 실제 연구 이용으로

IT(Information Technology, 정보기술) 분야에서는 사업마다 다른 질문을 던져야 한다. [AMD의 11월 3일 공식 실적](https://ir.amd.com/news-events/press-releases/detail/1303/amd-reports-third-quarter-2026-financial-results)은 회사 발표 기준 데이터센터 매출의 전년 대비 97% 증가와 게임 매출의 40% 감소를 함께 보여 줬다. 같은 기업 안에서도 수요의 방향이 같지 않았다. 이 숫자를 다음 주 Cisco 실적의 성장률이나 업계 전체의 공통 성과로 옮겨 읽을 근거는 없다.

**조건부 관찰:** Cisco가 11/13 한국시간 새벽 자료를 공개하면 AI(Artificial Intelligence, 인공지능) 네트워크와 관련해 이미 발생한 매출, 주문, 이후의 수요 기대를 구분할 필요가 있다. 설명회에서 구체적인 사업 범위와 기간이 드러나면 네트워크 투자가 어디에서 실제 성과로 이어지는지 판단을 좁힐 수 있다. 반대로 장기 수요 설명만 있다면 이번 분기의 검증된 결과로 바꾸지 않는다. 설명회가 열린다는 사실만으로 특정 숫자나 답변을 예고하지 않는다.

토요일에 다룬 [IBM 시카고 설치 발표](https://newsroom.ibm.com/2026-11-06-ibm-unveils-its-most-advanced-quantum-computer-in-chicago,-marking-a-milestone-for-illinoiss-quantum-future)는 Quantum System Two가 현재 Hyde Park Labs에서 가동 중이며 향후 연구단지로 이전할 예정이라고 설명한다. 양자컴퓨팅(Quantum computing, 양자역학의 성질을 이용해 정보를 처리하는 계산 방식)의 실제 설치와 유용한 응용 성과는 다른 단계다. 다음 주 개발자 회의에서 연구 자료가 나오면 어떤 문제를 풀었는지, 비교한 기존 계산 방법과 자원은 무엇인지, 다른 연구자가 같은 절차를 따라 확인할 수 있는지를 보자. 장비 가동이나 개발사의 우위 주장을 모든 업무의 계산 우위로 확대하지 않는다.

### AI — 오래 일하는 에이전트의 기억과 중단 경로

기업용 에이전트(agent, 목표에 맞춰 도구로 여러 단계의 일을 수행하는 프로그램)는 작업을 이어 가는 기능을 넓히고 있다. [Mistral의 11월 5일 공식 변경기록](https://docs.mistral.ai/resources/release-notes)은 Managed Agents의 장시간 실행, 중단 뒤 완료된 단계에서 재개, 사람의 승인 대기를 설명하면서 공개 미리보기(Public Preview, 정식 제공 전에 공개적으로 시험하는 단계)라고 표시한다. 같은 날 발표된 웹 연결 기능 일부는 제한된 비공개 미리보기다. 발표 묶음 전체를 누구나 쓸 수 있는 정식 기능으로 읽으면 실제 접근 조건이 사라진다.

작업을 이어 가는 능력에는 멈추는 경로도 필요하다. [Claude Enterprise 보안 문서](https://claude.com/resources/articles/claude-enterprise-security-updates)는 강제 로그아웃이 API(Application Programming Interface, 프로그램끼리 기능·데이터를 주고받는 접점) 키, 이미 실행 중인 클라우드 작업, 예약 작업까지 끝내지는 않는다고 명시한다. **조건부 관찰:** 다음 주 고객 사례나 관리 문서가 보강되면, 승인 대기·재개가 되는지만이 아니라 누가 권한을 회수할 수 있고 어떤 실행이 계속 남는지를 함께 확인하자. 통제 화면이 있다는 설명을 모든 경로의 차단 시험이 끝났다는 뜻으로 바꾸지 않는다.

토요일 뉴스의 [Anthropic 기억 연구](https://www.anthropic.com/research/components-of-agent-memory)도 이 흐름을 보완한다. 회사는 약 35만 개 내부 문서에 관한 25개 질문에서 검색만 썼을 때 채점 기준 충족률 53%, 정리된 위키와 검색을 함께 썼을 때 최고 61%, 위키만 썼을 때 최고 48%를 보고했다. 특정 실험의 자체 평가이며 보편적 업무 생산성이나 검색의 대체를 입증한 수치는 아니다. 여기서 위키(wiki, 서로 연결된 문서를 공동으로 정리·수정하는 지식 저장 방식)는 원문을 찾는 보조 구조다. 다음 주 기억 기능의 후속 사례가 나온다면, 저장량보다 원문을 다시 찾고 틀린 기록을 고치는 경로가 공개되는지를 보자. 정리 비용과 오래된 정보, 동시 수정의 충돌이 공개되지 않으면 좋은 시연만으로 장기 운영을 평가하기 어렵다.

### 모델 — 긴 입력과 높은 점수가 곧 신뢰성은 아니다

[LongCat의 현재 Quick Start](https://longcat.ai/platform/docs/)와 [매개변수 문서](https://longcat.ai/platform/docs/api/model-params)는 최대 출력 256K로 일치한다. 매개변수 문서의 정확한 값은 262,144토큰이다. 토큰(Token, 모델이 문장·데이터를 처리하는 기본 단위)의 입력과 출력을 합친 최대 길이는 1,048,576이다. 11/3 아카이브의 당시 문서 불일치를 현재도 남은 제한으로 되풀이하지 않는다. 문서 수정 시각과 계정별 실제 적용은 확인하지 않았다.

**조건부 관찰:** 다음 주 긴 자료를 처리한 결과가 나오면 입력할 수 있는 분량과 답변의 정확성을 나눠 보자. 핵심 근거를 원문에서 제대로 찾았는지, 중간 정보가 빠지거나 충돌할 때 어떻게 응답하는지, 출력 한도에 도달한 결과가 완성본처럼 쓰이지 않는지가 더 구체적인 판단 기준이다. 길이 한도가 커졌다는 것만으로 긴 문서 전체를 정확하게 이해했다고 결론 내릴 수 없다.

토요일의 [OpenAI BioBasicsBench 발표](https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science/)는 또 다른 사례다. 실험실 원자료를 다루는 100개 과제에서 회사가 제시한 GPT-6 Astra의 66.7%는 공통 xhigh 추론 설정에서 얻은 평균 획득 점수이며 실험 성공률이 아니다. 평가에는 부분 점수와 증거 부족을 알아채는 기준이 들어 있다. **조건부 관찰:** NVIDIA 서울 행사의 과학 연구 사례 등 후속 자료가 공개되면 평균 점수 외에 실패한 사례와 대조 조건, 결론을 보류한 이유까지 설명하는지 읽자. 서로 다른 평가의 숫자를 한 줄 순위로 묶거나 회사 평가를 독립 재현으로 소개하지 않는다. 다음 주 특정 모델 출시일은 확인하지 못했으므로 일정표에 넣지 않았다.

### 엔진 — 버전 이름보다 배포 파일과 회귀 검사를 본다

추론 엔진(inference engine, 모델을 불러 실제 결과를 계산하는 실행 소프트웨어)에서는 제공 상태를 정확히 읽는 일이 먼저다. [vLLM의 현재 릴리스](https://github.com/vllm-project/vllm/releases/tag/v0.33.0rc3)는 태그가 v0.33.0rc3이지만 제목은 v0.33.0이며, 11/8 확인한 GitHub 공개 정보의 사전 릴리스 표시는 false다. 태그의 rc만으로 아직 사전판이라고 단정하거나, 제목만으로 모든 배포 파일의 일관성이 검증됐다고 단정하지 않는다. 개발팀은 PyTorch 2.14와 CUDA(Compute Unified Device Architecture, 엔비디아 그래픽 처리 장치에서 범용 계산을 수행하는 플랫폼) 13.0 중심의 배포, CUDA 12.9용 사전 제작 파일 게시 중단을 명시한다. 이는 이전 환경에서 직접 빌드가 모두 불가능하다는 주장과 다르다.

**조건부 관찰:** 다음 주 전환 사례가 공개되면 실제 설치한 태그와 파일, 장치·드라이버·의존 소프트웨어를 함께 제시하는지 확인하자. 빠른 속도만이 아니라 이전에 되던 입력과 도구 호출이 유지되는지를 보는 회귀 검사(Regression testing, 변경 뒤 기존 기능이 다시 망가지지 않았는지 확인하는 시험)가 필요하다. 새 버전으로 바꿨다는 사실과 운영 준비가 끝났다는 판단 사이에는 이 검증이 남는다. 이 글은 패키지를 설치하거나 전환을 시험하지 않았다.

토요일 아카이브의 [llama.cpp b12177](https://github.com/ggml-org/llama.cpp/releases/tag/b12177)과 연결된 [#31563](https://github.com/ggml-org/llama.cpp/pull/31563)은 잘못된 UTF-8(Unicode Transformation Format–8-bit, 문자를 바이트로 표현하는 방식) 입력 때문에 명령줄 도구가 종료되는 경로를 다룬다. 잘못된 바이트를 대체하는 것과 원래 문자를 복구하는 것은 다르다. 이 변경은 전날 실시간 서버 입력 검사와도 별개다. 다음 주 후속 수정이 나오면 어떤 입력과 실행 경로에 적용되는지 좁혀 읽어야 한다. 현재 최신 버전 전체를 감사했다는 뜻은 아니며 실제 오류 재현은 하지 않았다.

### GitHub — 기억 도구의 기본 보관 설정이 달라졌다

월~수 GitHub 25카드는 작업 화면·기억·컴퓨터 조작·작업 폴더 분리·웹 수집처럼 에이전트 주변의 역할이 나뉘는 모습을 보여 줬다. 이는 선별한 아카이브의 제품 구성에 관한 해석이며 전체 개발자의 도입률이나 다음 주 인기 순위를 예측하는 통계가 아니다. 목·금 자료가 없고 주간 표시값과 일간 표시값의 기준도 다르므로 별 증가를 합산하지 않는다.

일요일 아침 재확인에서는 주중 기록 뒤의 실질적 변화가 있었다. [Claude-Mem v15.12.0](https://github.com/thedotmack/claude-mem/releases/tag/v15.12.0)은 11/8 04:51:33 KST에 공개됐으며, 에이전트가 읽거나 만든 이미지와 화면 캡처를 기본 보관하고 관련 기록에 연결한다고 설명한다. 릴리스는 이미지의 모델 추론 전송은 꺼져 있다고 밝히며, Keep images를 끄면 새 보관은 멈추지만 이미 보관한 이미지는 남고 사용자가 명시적으로 저장한 false 설정은 존중한다고 적는다. 이는 개발자의 변경 설명이며 이번 글이 실제 저장·전송 동작을 시험한 결과는 아니다.

이미지를 보관하지 않는 것, 모델에 보내지 않는 것, 기존 이미지를 지우는 것은 서로 다른 동작이다. **조건부 관찰:** 다음 주 기억 도구의 후속 문서와 사용 사례에서는 새 설치·업데이트·기존 설정 유지가 어떻게 다른지, 어디에 보관되고 삭제와 동기화가 어느 범위에 적용되는지 확인하는 편이 유용하다. 기능이 좋아졌다는 평가와 정보 보관 범위가 넓어졌다는 사실은 동시에 성립할 수 있다. 특정 사용자의 환경이나 자료를 확인하지 않았으며 설치나 사용을 권하는 글도 아니다.

## 전문가 전망과 검증 한계

이번 확인에서 다음 주의 특정 결과를 예측하는 독립 전문가의 직접 원문은 확보하지 못했다. NVIDIA·IBM의 연사 소개와 행사 주제는 주최자의 프로그램 안내이지, 아직 발표되지 않은 전문가 결론이 아니다. 회사 자체 연구·릴리스 설명과 편집자의 조건부 질문을 구분했고, 전문가 합의나 독립 재현을 만들어 넣지 않았다.

자료에도 시간의 층이 있다. 11/6 뉴스의 사후 보충은 정규 수집 마감을 늦춘 것이 아니며, 토요일 AI·IT 세 항목은 최초 시각이 확인되지 않은 참고 보충이다. 11/4 GitHub는 09:08 이후 실제 관찰로 평소 예약 시각의 스냅샷이 아니다. X 직접 원문의 접근 한계를 해소하지 못했으므로 한 파일의 반응을 여론의 대표값으로 쓰지 않았다. 현재 문서가 과거와 달라졌다고 과거 기록의 확인 시점까지 잘못됐다고 단정하지도 않는다.

또한 모든 기존 기사·저장소를 전수 재감사한 것은 아니다. 위 판단에 사용한 주요 원문을 다시 확인했으며, 실제 서비스 계정·파일 보관·외부 전송·모델 실행·성능·보안은 시험하지 않았다. IBM 상세 행사 연결은 조회 시간 초과로 개별 세션 시각을 확인하지 못해 공식 공지의 날짜만 남겼다. 자료가 공개되거나 조건이 바뀌면 같은 출처의 최신 상태를 다시 읽어야 한다.
