# 모델 브리핑 — 2026-10-22 (목요일, KST 아침)

발표 원문과 모델 카드를 확인했다. 정확한 게시 시각은 표시되지 않았으며, 공급자·개발자의 성능 수치를 독립 재현하지 않았다.

## 1. IBM, Granite Speech 5의 정확도·처리량·화자 기능을 나눠 개선

- **원문:** https://huggingface.co/blog/ibm-granite/granite-speech-5
- **분야:** 모델
- **날짜:** 2026-10-21 (원문은 날짜만 표시, 정확한 시각 미확인)

### 요약

IBM이 10월 21일 Granite Speech 제품군의 변경점을 설명했다. ASR(Automatic Speech Recognition, 자동 음성 인식)·번역용 20억 매개변수 모델, 빠른 전사용 4억7000만 매개변수 Turbo CTC(Connectionist Temporal Classification, 음성과 문자 대응을 학습하는 방식), 화자·시간 정보에 초점을 맞춘 4.1 2B Plus(20억 매개변수)를 구분했다. [20억 매개변수 모델 카드](https://huggingface.co/ibm-granite/granite-speech-5.0-2b)의 출시일은 10월 20일이므로 이날의 최초 출시로 해석하면 안 된다.

IBM은 새 20억 매개변수 모델의 영어 단문 평균 WER(Word Error Rate, 단어 오류율)이 5.06%라고 보고했다. 최대 2,000개 키워드로 고유명사 인식을 유도하고 잡음·잔향 대응도 개선했다는 설명이다. 이는 회사가 제시한 평가이며 이번 조사에서 독립 재현하지 않았다.

공식 전사 지원 언어는 영어·프랑스어·독일어·스페인어·포르투갈어·일본어다. 한국어는 포함되지 않는다. Apache 2.0 라이선스로 공개됐지만, 공개 접근성과 국내 회의 서비스에 대한 적합성은 별개로 평가해야 한다.

### 논조·다른 시각

- **기사 논조:** 긍정 — IBM은 정확도·처리량·활용 범위 확대를 강조한다.
- **다른 시각:** 관련 원문·모델 카드 및 웹 검색 범위에서 독립 반론 출처는 확인하지 못했다.
- **논조 점검:** [원문](https://huggingface.co/blog/ibm-granite/granite-speech-5)의 영어 단문 평가와 대규모 처리량을 한국어 정확도나 실시간 자막 지연으로 일반화할 수 없다는 것은 편집 분석이다.

**시사점:** 정확도·처리량·화자 구분 중 필요한 기능을 먼저 정하고, 실제 언어와 잡음 조건으로 시험해야 한다.

## 2. bekko, GPU 없는 검색을 겨냥한 다국어 정적 임베딩 공개

- **원문:** https://huggingface.co/blog/hotchpotch/bekko-static-embedding
- **분야:** 모델
- **날짜:** 2026-10-21 (원문은 날짜만 표시, 정확한 시각 미확인)

### 요약

개발자 Yuichi Tateno가 bekko-static-embedding-v1을 소개했다. 정적 임베딩(static embedding, 토큰마다 고정된 숫자 표현을 쓰는 방식)은 Transformer(입력 사이 관계를 계산하는 신경망)의 문맥 연산 대신 토큰별 고정 벡터를 찾아 평균낸다. [모델 카드](https://huggingface.co/hotchpotch/bekko-static-embedding-v1)는 MIT 라이선스와 공개 모델 파일을 제공한다.

개발자는 다국어 검색 평가 MNanoBEIR에서 43.76점을 얻어 비교한 다른 정적 모델보다 앞섰다고 보고했다. 그러나 같은 표의 문맥 기반 multilingual-e5-small은 51.17점으로 더 높다. “정적 모델 중 우수”와 “전체 검색 모델 중 최고”는 다른 주장이다.

개발자는 모델뿐 아니라 평가 도구 HAKARI-Bench도 개발한다고 밝혔다. 공개된 비교 수치는 유용한 출발점이지만 독립 검증을 대신하지 않는다. 이번 조사에서는 실제 한국어 문서에 대한 검색 품질이나 처리 속도를 재현하지 않았다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 개발자는 CPU(Central Processing Unit, 중앙 처리 장치) 중심의 저비용·고처리량 검색 가능성을 강조한다.
- **다른 시각:** 관련 원문·모델 카드 및 웹 검색 범위에서 독립 반론 출처는 확인하지 못했다.
- **논조 점검:** [원문의 비교표](https://huggingface.co/blog/hotchpotch/bekko-static-embedding)에서도 문맥 모델이 앞서므로, 속도상의 설계 이점을 정확도 우위로 확대하면 안 된다는 것은 편집 분석이다.

**시사점:** GPU(Graphics Processing Unit, 병렬 연산 장치) 없이 대량 문서를 인코딩할 때 검토할 만하다. 기존 검색 방식 및 작은 Transformer와 자체 질문·문서로 비교한 뒤 선택해야 한다.
