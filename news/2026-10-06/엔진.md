## 1. Strata — 125B MoE를 게이밍 GPU 한 장에서 돌리는 로컬 엔진

- **원문:** https://github.com/Niko1221/Strata (참고 기사: https://startupfortune.com/strata-lets-a-125-billion-parameter-model-run-on-a-gaming-gpu/)
- **분야:** 엔진 · 로컬 추론
- **날짜:** v0.1.38(10/3), v0.1.39(10/4)

### 미디어

![Strata 기사 대표 이미지 (StartupFortune)](https://startupfortune.com/wp-content/uploads/2026/10/strata-niko1221-qwen3-8-flash-next.jpg)

> 출처: 참고 기사 페이지 (StartupFortune) — 원본 이미지 링크(복제 저장 아님)

### 요약

Strata는 알리바바 큐원 팀의 125B 파라미터 MoE 모델 **Qwen3.8-Flash-Next** 를 소비자용 GPU(12GB VRAM급) 한 장에서 돌리는 MIT 라이선스 오픈소스 엔진입니다. 기존 도구처럼 트랜스포머 층 전체를 GPU↔CPU로 옮기는 **레이어 오프로딩(layer offloading)** 대신, 자주 쓰이는 **전문가(expert, MoE의 하위 네트워크)** 만 GPU에 캐시하고 나머지는 시스템 RAM에 두고 CPU로 계산하며, 큰 **n-gram 조회 테이블** 은 SSD에 두고 토큰마다 몇 줄만 읽는 방식입니다. 양자화는 ISTA-DASLab의 GSQ-RCO를 활용합니다.

v0.1.39에서는 디코딩 속도 개선, 병렬 요청, 구형 GPU 지원, **OpenAI Responses API 호환 엔드포인트(`POST /v1/responses`)** 가 추가됐습니다. 다만 3비트급 **양자화(quantization, 가중치 정밀도를 낮춰 메모리를 줄이는 압축)** 팩을 쓰므로 공식 벤치마크 대비 품질 손실이 있고, 저장소의 급격한 인기·코드 중 에이전트 작성 비중에 대한 커뮤니티의 의문도 함께 제기되고 있습니다.

### 미디어

![vLLM v0.31.0 릴리스 — GitHub 소셜 카드](https://opengraph.githubassets.com/722baa0faeed6800bc0a0599085d94f7ec55d6cf5ddcfcfea13a940c3be8140e/vllm-project/vllm/releases/tag/v0.31.0)

> 출처: 원문 페이지 (GitHub 릴리스, 자동 생성 소셜 카드) — 원본 이미지 링크(복제 저장 아님)

### 요약

**vLLM**(대규모 LLM 서빙용 오픈소스 엔진) 0.31.0은 717개 커밋, 307명 기여로 나왔습니다. 핵심은 재시작 비용과 멀티테넌트 안전성입니다.

- **`vllm preload`:** 양자화된 가중치를 GPU 메모리에 상주시키는 **가중치 캐시 데몬(daemon, 백그라운드 상주 프로세스)** — 엔진을 재시작해도 모델 로딩을 다시 안 해서 빠르게 복귀.
- **실험적 엔진 스냅샷:** `vllm snapshot create/restore` 로 **CRIU(실행 중인 프로세스 상태를 저장·복원하는 리눅스 도구)** 를 써서 초기화된 엔진을 통째로 복원.
- **Model Runner V2** 에 드래프트 모델 기반 **추측 디코딩(speculative decoding, 작은 모델이 먼저 초안을 쓰고 큰 모델이 검증해 속도를 높이는 기법)** 추가. DeepSeek-V4.1-Flash는 SM100(엔비디아 블랙웰 세대)에서 FlashMLA + NVFP4 압축 **KV 캐시(이전 토큰 계산 결과 저장소)** 가 기본값.
- **보안 강화:** 요청마다 넣는 멀티모달 인자는 `--trust-request-mm-kwargs` 플래그 없이는 거부, LoRA 이름과 `cache_salt` 간 **프리픽스 캐시 키 충돌** 수정.
- **주의(호환성 깨짐):** `tokenizer_mode="slow"` 제거, 온라인 FP8 방식 변경, 일부 플래그 이름 변경.

같은 날 공개된 **CVE-2026-105754**(CVSS 6.5, 중간)는 0.30.0 이전 버전의 **분리형 스케일아웃(disaggregated scale-out, 프리필·디코드를 별도 서버로 나눈 구성)** 경로에서 `/inference/v1/generate` 가 호출자가 보낸 멀티모달 텐서·캐시 해시를 검증 없이 받아, 엔진 종료(서비스 거부)나 다른 요청의 인코더 캐시 오염·조회가 가능했던 문제입니다. **0.30.0에서 수정**되었으므로 0.31.0 사용자는 영향 없음 — 구버전 운영 중이라면 업그레이드가 권장됩니다.

## 6. 결정 모델(Decision Model) API 확산 — Clef / Nimble / System One

- **원문:** https://blog.cloudflare.com/clef-decision-models/
- **분야:** 엔진 · API 표준 동향
- **날짜:** 10월 첫째 주

### 미디어

![Cloudflare 블로그 대표 이미지](https://blog.cloudflare.com/_emdash/api/media/file/01M3TJV43SPQCPKJ6GBXFCDKNE.01M3TJV53VYDMVNCZDPH1FBFYN.png)

> 출처: 원문 페이지 (Cloudflare 블로그) — 원본 이미지 링크(복제 저장 아님)

### 요약

**결정 모델(decision model)** 은 자유 문장을 생성하는 대신 "상태(state) + 유형이 정해진 질문들"을 받아 각 질문에 대한 답과 **확률** 을 빠르게 돌려주는, 분류·판정 특화 모델입니다(예: "이 티켓이 긴급한가?"). Cloudflare가 오픈소스 결정 모델 **Clef**(빠른 9B 버전 Clef-flash 포함)를 Workers AI에 공개한 데 이어, 엔진들이 일제히 대응 API를 붙였습니다:

- **llama.cpp:** `/v1/systemone` (System One 결정 API 형식)
- **SGLang:** `/v1/decisions`, `/v1/score`
- **Ollama:** Nimble·Clef 등 결정 모델 지원(로컬 `/v1/systemone`), MLX에서도 실행

에이전트가 매 단계 "어떤 도구를 쓸지/승인할지" 같은 판단을 저렴·저지연으로 처리하려는 수요가 반영된 흐름입니다.
