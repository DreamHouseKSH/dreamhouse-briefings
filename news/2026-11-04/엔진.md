### 요약
Ollama v0.40.14가 정식 릴리스로 게시됐다. 주요 수정은 OpenAI 호환 API(Application Programming Interface, 프로그램끼리 요청·결과를 주고받는 연결 규칙)에서 사용자가 생성 설정을 생략했을 때 모델에 포함된 기본 설정을 지키는 것이다. 기존처럼 temperature(답변 선택의 무작위성을 조절하는 값)와 top_p(누적 확률로 후보 범위를 제한하는 값)를 1.0으로 덮어쓰지 않고 자체 채팅 경로와 동작을 맞췄다고 설명한다.

Claude Code 연결에서는 모델의 출력 길이 제한을 적용하고, 클라우드 웹 검색의 압축 응답 해석과 이전 답변 내용 보존도 수정했다. ChatGPT 연결 해제 실패의 재시도와 Codex 연결 경로 확인도 포함된다. 속도 경쟁보다 호출 경로에 따라 답변 설정·오류 처리가 달라지는 문제를 정리한 업데이트로 읽을 수 있다.

같은 조사 구간의 v0.40.15-rc0는 시험용 사전 릴리스다. Linux에서 묶음 제공되는 연산 라이브러리를 불러오는 변경과 MiMo V2.6 모델 지원을 명시하지만, 정식 v0.40.14의 기능으로 섞어 소개하지 않았다. 기존 모델을 엔진이 지원하게 된 것과 모델 자체의 최초 발표는 별개의 사건이다.

### 요약
llama.cpp의 b12079는 NCCL(NVIDIA Collective Communications Library, 여러 그래픽 연산 장치 사이의 데이터 교환을 돕는 라이브러리)을 이용한 다중 노드 텐서 병렬 처리를 추가했다. 텐서 병렬 처리(Tensor Parallelism)는 모델 계산을 여러 장치로 나누는 방식이다. 변경 기록은 서로 다른 프로세스의 집단 통신 인터페이스와 지원되는 원격 실행 경로의 활용을 설명한다.

b12078은 GGUF(모델 가중치와 실행 정보를 담는 파일 형식) 분할 파일을 합칠 때 서로 맞지 않는 조각을 거부하도록 바꿨다. b12081은 수를 낮은 정밀도로 표현하는 양자화(Quantization) 계산 경로의 보정 합계에 ‘잠재적 수정’을 적용했다. 원문이 확정적인 해결 대신 가능성을 표현하므로 모든 환경의 오류가 해결됐다고 단정하지 않았다.

세 태그는 공식 릴리스 정보에서 모두 사전 릴리스로 표시된다. 다중 노드 지원의 추가만으로 특정 하드웨어·모델의 속도 향상이 입증된 것은 아니다. 확인 시점에 더 나중 태그가 있었지만 오전 08:01 이후 게시된 b12083·b12084는 이번 고정 조사 구간에서 제외했다.
