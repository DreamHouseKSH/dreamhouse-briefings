## 1. vLLM, 미디어 페치에 마감시간 부여 — 느린 이미지 URL 하나가 풀링 워커를 마비시키던 구멍 (보안·브레이킹)

- **무슨 일인가:** vllm-project/vllm에서 동기식 미디어 응답 본문 읽기와 재시도가 이제 해당 모달리티 설정 fetch 타임아웃의 2배라는 공동 마감시간을 공유한다. 또 텍스트 전용 풀링 모델은 이미지·오디오·비디오 입력을 외부 요청을 보내기 전에 거부한다. 겨냥한 시나리오는 '응답이 느린 이미지 URL 하나가 풀링 렌더러의 유일한 워커를 붙잡아 두는' 정지(stall). vLLM은 이 변경을 보안(security) 태그와 함께 BREAKING으로 표시했으므로, 풀링 요청으로 미디어 URL을 라우팅하는 배포는 업데이트 전 검토가 필요하다. (RepoJournal Local LLMs 2026-11-25 07:00 UTC, 구간 경계 — 집계 시점 기준 24시간 내 커밋으로 사실상 구간 내)
- **논조:** 외부 URL을 대신 가져오는 서버의 고전적 취약점(무한 대기)을 타임아웃 설계로 닫은 정통 보안 패치다.
- **다른 시각:** 마감시간은 완화일 뿐 근본 차단은 아니다(SSRF 표면은 그대로). BREAKING 표시가 말하듯 기존 동작에 의존하던 배포는 동작이 바뀐다.
- **시사점:** 멀티모달 서빙이 늘수록 'URL을 받아오는 추론 서버'의 네트워크 안전 설계가 필수 덕목이 된다. 운영자는 변경 로그의 보안·브레이킹 태그를 배포 게이트로 쓸 만하다.

## 2. SGLang, 디퓨전 서버에 API 키 도입 — 가중치·LoRA·메모리·프로파일링 경로가 무인증이었다

- **무슨 일인가:** sgl-project/sglang의 디퓨전 서버에는 API 키 지원이 없어서, /update_weights_from_disk, /v1/set_lora, 메모리 해제, 프로파일링 같은 제어 경로가 포트에 닿을 수 있는 누구에게나 응답했다. 새 --api-key와 --admin-api-key 인자가 이 경로들을 게이트하며, 관리자 키는 LLM 서버와 마찬가지로 SGLANG_ADMIN_API_KEY 환경 변수로 폴백하고 두 키 모두 서버 인자에 남지 않는다. 같은 회차에 두 가지 버그 수정도 포함됐다: ① 등록된 환경 변수 값이 파싱에 실패하면 경고만 남기고 조용히 기본값으로 돌아가던 문제(예: SGLANG_PORT=not-a-port가 None이 되어 아무도 요청하지 않은 설정으로 기동) — 이제 변수명과 파싱 실패를 명시하는 ValueError를 던진다. ② 스트리밍 청크에 완결된 도구 호출이 여러 개 실릴 때 첫 번째만 처리하고 나머지를 버리던 function_call 버그 — 이제 청크 내 모든 완결 호출을 처리한다. (RepoJournal Local LLMs 2026-11-25 07:00 UTC, 구간 경계)
- **논조:** "포트만 열려 있으면 가중치를 바꿀 수 있었다"는 설정은 내부망 신뢰를 전제한 초기 설계의 흔적이다.
- **다른 시각:** 키 게이트는 최소선이다. 관리 경로 분리, 네트워크 분리 같은 방어 심층은 여전히 배포자 몫이다.
- **시사점:** 추론 서버의 관리 표면이 커지면서 '기본 무인증' 관행이 빠르게 청산되고 있다. 환경 변수 파싱 버그 같은 '조용한 폴백' 수정은 보안보다 운영 신뢰성의 문제로 더 자주 사고를 만든다.

## 3. llama.cpp, CUDA 융합 경로를 MROPE/IMROPE로 확장 + ARM SVE q5 커널 추가

- **무슨 일인가:** ggml-org/llama.cpp의 융합 rms_norm_mul_rope CUDA 경로가 MROPE와 IMROPE를 커버하게 돼 Qwen3-VL, Qwen3.5, Qwen3.8 계열이 이 경로에 올라탔다. head_dim 128·256에서 융합 경로가 오히려 느렸던 원인(ncols 1024 미만이면 항상 행당 256 스레드 실행)도 손봤다 — ncols 256 이하의 다중 토큰 실행은 32 또는 64 스레드를 쓴다(RTX에서 테스트). ARM 쪽에서는 ggml-cpu에 SVE 최적화 q5_0×q8_0, q5_1×q8_1 내적 커널이 추가됐다(상위 양자 비트의 벡터 길이별 언패킹, SVE 없는 CPU는 NEON 폴백). 별도로 mlx는 CUDA LayerNorm 스크래치 재사용 버그(모든 워프가 읽기 전에 덮어씀)와 BNNS·simd의 반정밀 GEMM 차원 오류를 고쳤다. (RepoJournal Local LLMs 2026-11-25 07:00 UTC, 구간 경계)
- **논조:** '융합 경로가 느린 코너'를 프로파일링으로 찾아 스레드 매핑을 바꾼 정통 커널 튜닝이다.
- **다른 시각:** 수치는 RTX 단일 테스트 기준. 다른 GPU 세대·배치 조합에서는 재검증이 필요하다.
- **시사점:** 비전-언어 모델(MROPE 계열)이 llama.cpp의 1급 최적화 대상이 됐다. ARM SVE 커널 추가는 서버급 ARM CPU에서의 로컬 추론 최적화 경쟁이 계속된다는 신호다.
