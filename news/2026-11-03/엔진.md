## 2. SGLang 새 버전, 더 빠른 추론에도 하드웨어 조건이 붙는다

### 요약

추론 속도 개선은 같은 모델이라도 장비와 요청 방식에 따라 달라집니다. SGLang은 새 버전에서 여러 모델 지원과 저지연 실행 경로를 추가했습니다. 저지연은 답을 더 빨리 돌려주는 것을 뜻하며, 많은 요청을 한꺼번에 처리하는 처리량과는 다른 평가 기준입니다.

이번 저지연 경로는 사용자가 선택해서 켜는 추가 기능입니다. 개발팀은 DeepSeek 계열 모델의 한 사용자 디코딩에서 엔비디아 GB300은 최대 44%, AMD MI350X는 최대 75% 개선됐다고 설명합니다. 디코딩은 입력을 읽은 뒤 출력 토큰을 차례로 생성하는 단계입니다. 서로 다른 장비의 수치를 일반적인 엔진 간 우열이나 모든 사용자 환경의 속도 향상으로 바꾸어 읽으면 안 됩니다.

릴리스에는 GPU 메모리보다 큰 전문가 혼합 모델을 다루는 선택 기능과 구글 TPU용 실행 플러그인도 포함됐습니다. 전문가 혼합은 여러 계산 모듈 중 일부를 선택해 쓰는 모델 구조입니다. 지원 경로가 늘어났다는 사실과, 개인 장비에서 원하는 지연·메모리 사용량을 달성한다는 사실은 별개이므로 작은 검증 작업부터 확인하는 접근이 적절합니다.

## 3. llama.cpp의 Clover 지원, 우선은 순차 생성 범위부터

### 요약

모델 지원이 추가됐다고 모든 생성 방식이 함께 들어오는 것은 아닙니다. llama.cpp의 새 빌드는 Clover 모델을 읽고 실행하는 경로를 추가했습니다. 이번에 병합된 범위는 앞선 출력을 바탕으로 다음 토큰을 하나씩 만드는 자기회귀 방식입니다.

공식 변경 제안은 모델 파일 변환과 로딩, 주의 집중 계산 경로를 포함하며 자기 추측 생성은 별도 변경으로 분리했다고 명시했습니다. 자기 추측 생성은 같은 모델 구조를 활용해 여러 후보 토큰을 미리 만들고 검증하는 방식입니다. 따라서 새 빌드에 Clover라는 이름이 보인다는 이유로 그 가속 방식까지 완성됐다고 소개하지 않았습니다.

제안 작성자는 CPU와 엔비디아 H200에서 지정 정밀도로 추론을 검증했다고 적었습니다. 이는 개발자가 보고한 검증 범위이며 모든 양자화 파일·장비 조합을 보장하지 않습니다. 릴리스는 사전 릴리스로 표시됐으므로 기존 안정적인 실행 환경을 대체하기 전에 실제 사용할 파일과 하드웨어 조합을 별도로 확인할 필요가 있습니다.

- **기사 논조:** 공식 변경 기록은 새로운 모델 호환성 추가를 알리는 기술 중심 공지입니다.
- **논조 점검:** 이번 확정 범위는 자기회귀 실행이며, 자기 추측 생성이나 모든 하드웨어의 성능 향상을 포함하지 않습니다.
- **다른 시각:** [같은 변경 제안의 공개 테스트 토론](https://github.com/ggml-org/llama.cpp/pull/31306)에는 병합 전 개발 버전의 자기 추측 실행이 특정 GB10 환경에서 오히려 느렸다는 이용자 보고가 있습니다. 이는 제한된 사전 테스트이며 현재 병합된 자기회귀 경로의 성능 결론으로 옮겨 쓰지 않았습니다.

**시사점:** 지원 모델 이름보다 어떤 실행 방식까지 병합됐는지 확인하는 것이 로컬 추론 도구의 업데이트를 정확하게 읽는 방법입니다.
