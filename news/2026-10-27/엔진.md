### 요약

llama.cpp가 OpenCL(Open Computing Language, 여러 제조사 연산 장치에서 병렬 계산을 수행하는 규격) 경로의 상태 복원 오류를 수정했습니다. 대상은 KV 캐시(Key-Value cache, 앞서 처리한 입력의 계산 결과를 보관하는 공간)를 다시 불러오는 코드입니다. 일부 압축 캐시 형식에서 저장 공간의 일부를 가리키는 뷰(view)에 실제 데이터를 쓰지 않은 채 복원이 끝난 것으로 처리했습니다.

개발자가 공개한 재현에서는 긴 다른 요청을 처리한 뒤 이전 프롬프트를 캐시에서 복원하면, 현재 질문 대신 앞선 요청의 내용을 바탕으로 답하는 문제가 나타났습니다. 다른 저장 형식에서도 뷰의 시작 위치를 반영하지 않아 첫 번째가 아닌 처리 흐름의 데이터를 잘못 쓸 수 있었습니다. 변경은 이 저장 경로를 바로잡습니다. 공개 자료만으로 실제 서비스의 이용자 간 유출이나 보안 사고가 발생했다고 단정할 수는 없습니다.

시험은 개발자의 Adreno X2-90과 Gemma-4-E4B 구성에서 수행됐습니다. 상태 저장·복원과 일부 복사 시험의 실패가 통과로 바뀌었지만, 장치 내부 복사 경로의 압축 캐시 실패는 이 변경의 시험에서 그대로였으며 별도 수정 #30541의 범위라고 PR이 설명합니다. 모든 장치·모델의 캐시 문제를 해결했다는 뜻이 아니라 특정 복원 경로의 수정입니다.

## 2. Metal 큰 행렬 출력의 주소 계산 확대 — 대용량 조건의 오류 방지

- **원문:** [b11895 릴리스](https://github.com/ggml-org/llama.cpp/releases/tag/b11895) · [변경·검토·시험 기록 #30072](https://github.com/ggml-org/llama.cpp/pull/30072)
- **분야:** 엔진 · Mac 연산 안정성
- **날짜:** 2026-10-26 18:54 KST (릴리스)

### 요약

llama.cpp는 애플 Metal의 큰 행렬 출력에서 메모리 위치 계산이 넘치는 문제를 수정했습니다. Metal은 애플 기기에서 그래픽과 병렬 계산을 처리하는 기술입니다. 이번 변경은 행렬 곱셈 결과를 저장하는 위치 계산의 정수 폭을 넓혀, 매우 큰 출력에서 주소가 잘못 계산되는 상황을 막는 데 초점을 맞춥니다.

검토 과정에서는 최초 수정 외의 저장 경로와 토큰 인덱스도 논의됐고 추가로 보완됐습니다. 개발자는 M4 Pro에서 일반 경로와 명시적으로 활성화한 텐서 경로를 시험했다고 설명했습니다. 텐서(Tensor)는 계산용 숫자를 여러 차원으로 배열한 자료입니다. 다만 M5 하드웨어에서 시험한 것은 아니라고 밝혔으며, 대용량 합성 시험의 일부는 마지막 변경 후 다시 실행하지 않았다고 기록했습니다.

이 소식은 모든 긴 문맥 오류가 해소됐거나 모델 처리 속도가 빨라졌다는 발표가 아닙니다. PR 검토에는 다른 행렬·벡터 연산 경로가 별도 후속 문제라는 설명도 있습니다. 큰 입력을 다루는 Mac 사용자는 릴리스 번호와 실제 실행 경로를 함께 확인해야 수정의 관련성을 판단할 수 있습니다.

- **논조 점검:** 작성자의 시험 보고가 근거이며 하드웨어 범위가 제한됩니다. 합성 시험을 실사용 전체의 안정성 보증으로 해석하지 않았습니다.
- **다른 시각:** [PR 검토와 작성자 후속 답변](https://github.com/ggml-org/llama.cpp/pull/30072)은 빠진 경로를 지적하고 보완 범위와 미시험 조건을 구분합니다. 이는 프로젝트 내부 검토이며 독립 실사용 평가와는 다릅니다. 외부 반론은 찾지 못했습니다 (검색 범위: `llama.cpp 30072 Metal`, 관련 GitHub 기록).

**시사점:** 메모리 용량이 충분하더라도 내부 주소 계산의 한계가 별도 장애 원인이 될 수 있습니다. 이번 수정은 용량 확대나 성능 향상이 아닌 계산 정확성 개선으로 읽는 것이 맞습니다.
