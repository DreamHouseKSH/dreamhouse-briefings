## 1. vLLM v0.34.0 출시 — 1,061개 커밋, Model Runner V1 제거·기본값 대폭 변경

- **원문:** https://github.com/vllm-project/vllm/releases · https://ai-eng-digest.astgl.ai/sections/local.html (11-17 정리)
- **분야:** AI 추론 엔진 · 서빙
- **최초 게시:** vLLM 릴리스 2026-11-16 18:22 ET (11-17 08:22 KST)
- **시간 판정:** 정규 구간 내 확인(구간 시작 직후)

### 요약

vLLM v0.34.0이 16일(미국시간) 릴리스됐다. 412명의 기여자, 1,061개 커밋 규모다. 업그레이드 전 확인할 파괴적 변경이 여럿이다. ① Model Runner V1이 제거돼 `VLLM_USE_V2_MODEL_RUNNER=0` 강제 지정은 시작 단계에서 실패한다. ② 기본 `--block-size`가 16에서 64로 바뀌고(ROCm 페이징드 어텐션은 16 유지), ③ 확장형 KV 캐시가 기본 켜짐과 함께 `gpu_memory_utilization` 기본값이 1.0이 됐다 — 이전 동작을 원하면 `--gpu-memory-utilization 0.9`나 `--no-enable-extensible-kv-cache`로 되돌려야 한다. ④ ROCm 7.2 아티팩트 지원이 끝났고(10.0 필요), QuTLASS/fp_quant·Marlin W4A8·Keye-VL이 제거됐다. ⑤ `huggingface_hub >= 2.0.0`, `tokenizers >= 0.23.3`, `timm >= 1.0.30`이 필요하다.

새 지원 모델에는 Mistral Large 4(1T 파라미터/52B 활성), MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, Ripple-65B Preview, LFM3 패밀리 등이 포함됐다. CRIU + cuda-checkpoint 기반 체크포인트/복원 엔드포인트와 내결함성 DP+EP 스케일다운, 기본 켜짐의 NUMA 바인딩도 들어왔다. 릴리스 노트는 더 큰 캐시(예: H200의 MiniMax-M3가 43.3만→67.2만 토큰)와 최대 1.95배 디코딩 가속(4×GB200 등)을 보고하지만, 일부 H200 모델에서는 동시성 128 기준 TPOT(토큰당 출력 시간)이 6~18% 나빠졌다고 명시한다. 성능 수치는 프로젝트 자체 측정이다.

### 논조·다른 시각

- **기사 논조:** 사실 전달 — 릴리스 노트와 다이제스트 정리다.
- **논조 점검:** 대규모 기본값 변경(블록 크기, 메모리 활용률)은 기존 배포의 동작을 바꿀 수 있다. 무심코 업그레이드하면 메모리 사용 패턴이 달라지는 버전이다.
- **다른 시각:** 캐시 용량 확대와 일부 모델의 지연 증가가 같은 릴리스에 공존한다. 워크로드별로 이득과 손해가 갈리므로 자기 환경에서의 측정이 필수다.

**시사점:** V2 전환을 마무리하는 정리 릴리스다. 운영 환경은 기본값 변경 세 가지(블록 64, KV 확장, 메모리 1.0)를 먼저 검토하고 올려야 한다.

## 2. llama.cpp, 구형 batch API 폐기 예고 — Metal CONV_2D 행렬곱 전환으로 최대 17.8배

- **원문:** https://github.com/ggml-org/llama.cpp (PR #32306, #28069, #32032 등) · https://ai-eng-digest.astgl.ai/sections/local.html
- **분야:** AI 추론 엔진 · 개발 동향
- **최초 게시:** 2026-11-16 ~ 11-17 (PR 병합일 기준)
- **시간 판정:** 정규 구간 내 확인

### 요약

v1.0.0 이후 첫 API 정리가 나왔다. 16일 병합된 #32306은 `llama_batch`를 폐기 예정(deprecated)으로 표시하고 호출자에게 `llama_batch_ext`로의 이전을 요구한다. 같은 시각 병합된 #32356은 Swift 예제를 포함한 저장소 내 모든 코드를 새 API로 옮겼고, 이전 안내서(#32163)는 아직 열려 있다. v1.0.0 정책상 공개 C API 심볼 제거는 메이저 버전 상향이 필요하므로, 실제 제거는 2.0에서야 가능하다. 두 PR 모두 작성자 검토를 거친 AI 보조 코드임을 밝혔다.

성능 쪽에서는 17일 병합된 #28069가 Metal(애플 실리콘)의 2D 컨볼루션을 simdgroup 행렬곱으로 전환했다(f16 스테이징, f32 누산; 구 커널은 폴백으로 유지). 작성자의 Apple M5 측정표 기준으로 형태에 따라 2.2배에서 최대 17.8배 빨라졌으며, 텍스트 디코딩이 아니라 비전·오디오 인코더에 해당하는 변경이다. 이 밖에 Inkling 채팅 파서(#32381), Inkling mmproj 변환 수정(#32430), 웹 UI의 'Llama Chat' 개명 및 `ui/apps/chat` 이동(동작 변경 없음, #32032), CUDA K/V 타일 읽기 회전으로 긴 컨텍스트 프리필 개선(#32407, 작성자 측정 RTX 5090에서 12.8만 깊이 기준 최대 1.41배)이 병합됐다. 모두 나이틀리 채널이며 정식 태그는 v1.0.0 이후 아직 없다(최신 나이틀리 b12473).

### 논조·다른 시각

- **기사 논조:** 사실 전달 — 병합 로그 정리다.
- **논조 점검:** 배수 성능 수치는 작성자 측정치다. API 폐기 예고는 지금 당장 깨지는 것이 아니라 이전 여유를 주는 공지다.
- **다른 시각:** llama.cpp를 라이브러리로 쓰는 프로젝트는 마이그레이션 가이드(#32163) 완료 전에 서두를 필요가 없다. v1 정책상 제거 전 메이저 버전업이 선행된다.

**시사점:** 1.0 선언 이후에도 개발 속도는 유지되면서 '안정화 약속'과 '롤링 개선'이 공존하는 형태가 잡혀 가고 있다.

## 3. [후속] Homebrew·ggml 1.0 링크 문제 — "버그가 아니라 예상된 동작"으로 종결

- **원문:** https://github.com/ggml-org/llama.cpp (releases-and-versioning 스레드) · https://ai-eng-digest.astgl.ai/sections/local.html
- **분야:** AI 추론 엔진 · 패키징
- **최초 게시:** 스레드 정리 2026-11-16 ~ 11-17
- **시간 판정:** 정규 구간 내 확인

### 요약

어제 엔진 브리핑 2번에서 다룬 Homebrew의 whisper-cli 링크 문제가 '버그 아님'으로 정리됐다. 16일 릴리스·버저닝 스레드에서 Homebrew 메인테이너 p-linnane이 설명했다: Homebrew는 각 포뮬러의 최신 버전만 배포하며, whisper.cpp는 같은 풀 리퀘스트(Homebrew/homebrew-core#325280)에서 ggml 1.0.0에 맞춰 다시 빌드됐고, whisper-cli를 샘플에 실행하고 libwhisper·ggml에 대해 빌드하는 테스트가 CI에서 통과했다는 것이다. 즉 '구버전 링크'가 아니라 '최신 버전으로의 동시 전환'이었다. ggerganov는 17일 이 설명을 수용했고, 다이제스트는 전날의 "업그레이드 보류" 권고를 철회했다.

### 논조·다른 시각

- **기사 논조:** 사실 전달 — 이슈 종결 기록이다.
- **논조 점검:** 초기 보고(실행 실패)와 최종 설명(예상된 동작)이 다르다. 패키지 전환기에는 동일 현상이 환경에 따라 다르게 나타날 수 있어, 초기 보고가 틀렸다기보다 원인 규명이 진전된 것이다.
- **다른 시각:** Homebrew의 '최신만 유지' 정책과 Debian의 '버전 공존(SOVER)' 정책 차이가 이번 혼선의 배경이다. 여러 채널을 쓰는 팀은 채널별 정책 차이를 알아두는 편이 좋다.

**시사점:** ggml 1.0 전환의 패키징 소동은 하루 만에 매듭지어졌다. Homebrew 사용자는 업그레이드해도 된다.
