## 1. llama.cpp b11499 — CUDA roll non-contiguous 수정·다중 플랫폼 바이너리

- **원문:** https://github.com/ggml-org/llama.cpp/releases/tag/b11499
- **분야:** 엔진 · llama.cpp
- **날짜:** 2026-10-08

### 요약

ggml-org **llama.cpp**가 8일(UTC) 프리릴리스 **b11499**를 올렸습니다. 핵심 변경은 CUDA 백엔드에서 **roll 연산(텐서를 축 방향으로 순환 이동)** 이 **non-contiguous(메모리상 연속이 아닌)** 텐서도 바이트 스트라이드로 처리할 수 있게 한 수정(#29547)입니다. GPU에서 일부 연산이 깨지던 케이스를 줄이는 성격입니다.

동시에 macOS Apple Silicon·Intel, iOS XCFramework, Ubuntu CPU/Vulkan/CUDA 12·13/ROCm/SYCL/OpenVINO, Windows CPU·CUDA·Vulkan·ROCm·SYCL, Android·Snapdragon 등 다수의 사전 빌드 바이너리가 함께 게시됐습니다. 로컬·서버 모두 최신 빌드를 받아 쓰기 쉬운 날입니다.

### 논조·다른 시각

- **기사 논조:** 중립 — 자동 생성되는 릴리스 노트로, 변경 1건(#29547)과 바이너리 목록만 담겨 있습니다.
- **논조 점검:** 특별한 문제 없음 — 1차 출처(GitHub 릴리스)이고 평가성 표현이 없습니다. 다만 GitHub에서 **프리릴리스**로 표시된 빌드이고, 우리 요약의 'GPU에서 깨지던 케이스를 줄인다'는 PR 제목을 보고 해석한 것입니다.
- **다른 시각:**
  - 찾은 반론 없음 (검색 범위: GitHub 릴리스·PR, 웹 검색. 일상적인 빌드라 별도 보도나 반응이 없음).

**시사점:** 기능 폭주보다는 CUDA 안정성·배포 바이너리 갱신 위주 릴리스입니다. GPU에서 roll 관련 이상을 겪던 사용자는 b11499 이후 빌드로 올려 확인하면 됩니다.

## 2. Ollama v0.40.1 — 클라우드 usage/balance API 프록시·Windows 대용량 모델 수정

- **원문:** https://github.com/ollama/ollama/releases/tag/v0.40.1
- **분야:** 엔진 · Ollama
- **날짜:** 2026-10-07

### 미디어

![Ollama v0.40.1 GitHub 릴리스 OG 카드](https://opengraph.githubassets.com/e34ee48651b082903cba6e5032b0693a9f10ec470dd317ed63f23634e8e96552/ollama/ollama/releases/tag/v0.40.1)

> 출처: GitHub Releases (ollama/ollama) — 원본 이미지 링크(복제 저장 아님)

### 요약

Ollama가 **v0.40.1**을 냈습니다. 서버가 클라우드 **usage·balance API(사용량·잔액 조회)** 를 프록시할 수 있게 됐고(#18829), Windows에서 2GiB를 넘는 모델 헤드 읽기 버그(#18777)·매니페스트 **심볼릭 링크(바로가기형 파일 링크)** 회피(#18852)가 들어갔습니다. CLI 온보딩에서 계정 단계가 빠졌고(#18826), 업스트림에 반영된 MLX Metal residency 패치는 제거됐습니다(#18854).

로컬 모델 워크플로에서 Windows 대용량 GGUF 로딩 이슈와 클라우드 계정 잔액 조회를 같이 쓰는 사용자를 겨냥한 패치 릴리스입니다.

### 논조·다른 시각

- **기사 논조:** 중립 — 공식 변경 목록(PR 링크)만 있습니다.
- **논조 점검:** 특별한 문제 없음 — 1차 출처입니다. 다만 이번 릴리스의 첫 항목이 **클라우드 계정(사용량·잔액) 기능**이라, 로컬 우선 사용자 쪽에서는 이것만으로도 논쟁거리가 될 수 있습니다(아래).
- **다른 시각:**
  - 로컬 우선 사용자의 우려: `:cloud` 태그 모델은 로컬 모델과 같은 API를 쓰지만 실제로는 프롬프트를 Ollama 데이터센터로 보냅니다. 개인정보 때문에 Ollama를 쓴다면 모델 목록을 점검하라고 권합니다 ([AIFoss](https://aifoss.dev/blog/ollama-cloud-proxy-models-privacy-guide-2026/)).
  - 공식 대응책: `OLLAMA_NO_CLOUD=1` 환경변수나 `~/.ollama/server.json`의 `disable_ollama_cloud`로 클라우드 기능을 끄고 로컬 전용으로 쓸 수 있습니다 ([Ollama FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx)).

**시사점:** 메이저 기능보다 운영·Windows 안정성·클라우드 계정 연동 정리에 가깝습니다. Windows에서 큰 모델을 쓰는 팀은 0.40.1로 올리는 편이 안전합니다.
