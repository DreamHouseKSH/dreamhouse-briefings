- **최초 게시:** RepoJournal 2026-11-23
- **시간 판정:** 정규 구간 내 확인

### 요약

llama.cpp의 채팅 파싱이 텍스트 기반에서 토큰 기반으로 바뀌었다. 기존 파서는 순수 텍스트로 동작해, Qwen3+ 출력이 `</think>`를 `</` `think` `>` 같은 별개 조각으로보낼 때 이를 추론 경계(reasoning boundary)로 잘못 읽었다. 새 파서는 토큰으로 동작해 전용 특수 토큰만 경계로 인식한다. RepoJournal은 이를 "이날 가장 중요한 변경"으로 꼽고, 추론 마커를 원문 텍스트에서 후처리로 제거하던 클라이언트는 이 빌드에서 재시험하라고 권한다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 수정 커밋 전달형이다.
- **논조 점검:** 동작 변경이므로 텍스트 기반 후처리를 쓰는 클라이언트는 회귀 시험이 필요하다.
- **다른 시각:** '토큰과 텍스트의 경계' 문제는 스트리밍 파싱의 고전이다. 특수 토큰만 신호로 쓰는 방향은 파서 신뢰성의 정석이다.

**시사점:** 추론 모델 출력을 스트리밍으로 파싱하는 서빙·클라이언트는 이번 변경이 직접 영향이다. 재시험 대상 목록에 넣을 커밋이다.

## 2. MLX, CPU 양자화 행렬곱 누산을 float32로 — mxfp4 오차 2.6e-2→3.0e-3

- **원문:** https://repojournal.com/showcase/local-llm (RepoJournal Local LLMs 와이어, 2026-11-23)
- **분야:** 엔진 · MLX
- **최초 게시:** RepoJournal 2026-11-23
- **시간 판정:** 정규 구간 내 확인

### 요약

MLX의 CPU 양자화 커널(mxfp4, nvfp4, mxfp8)이 `quantized_matmul`과 `gather_qmm`에서 bf16/fp16으로 누산하던 것을 float32 누산기로 변경했다. `affine`에 적용됐던 #4803와 같은 방향이다. K=4096, bf16 기준으로 mxfp4 오차가 2.6e-2에서 3.0e-3으로 줄어 GPU 수치(3.1e-3)에 근접했다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 정밀도 수정 전달형이다.
- **논조 점검:** float32 누산은 정확도 대신 속도와의 교환이다. 종단 간 성능 영향은 커밋 수치만으로는 알 수 없다.
- **다른 시각:** 저비트 양자화(4비트 계열)의 CPU 정확도가 GPU와 맞춰지는 것은 애플 실리콘 로컬 추론의 재현성을 높인다.

**시사점:** 같은 모델을 CPU/GPU에서 번갈아 돌리는 워크플로의 출력 차이가 줄어든다. 정밀도 민감 작업은 갱신 후 재비교할 가치가 있다.

## 3. SGLang, 추론 성능 두 건 — MTP 드래프트 프리필 KV 최적화와 diffusion 오프로드 수정

- **원문:** https://repojournal.com/showcase/local-llm (RepoJournal Local LLMs 와이어, 2026-11-23)
- **분야:** 엔진 · SGLang
- **최초 게시:** RepoJournal 2026-11-23
- **시간 판정:** 정규 구간 내 확인

### 요약

SGLang에 성능 변경 두 건이 들어갔다. ① 추측적(speculative) 디코딩에서 MTP 드래프트의 어텐션·DSA 인덱서·MoE를 각 요청의 마지막 프롬프트 토큰에만 실행하고 나머지는 KV 캐시 기록만 하게 했다. 드래프트 출력이 실제로 쓰이는 토큰이 마지막뿐이기 때문이다. GLM-5.3-Flash, MTP 5/1/6 설정에서 8천 토큰 프롬프트의 입력 처리량이 동시 요청 1·8·32에서 2.8~3.7% 올랐다. ② diffusion 컴포넌트 오프로드에서 매 사이클마다 불변 가중치를 디바이스→호스트로 전체 복사하던 것을 제거해, RTX 5090에서 MiniMax-H3의 9.7GiB 비디오 VAE 스왑아웃 비용이 첫 사이클 4.85초에서 0.37초로 줄었다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 커밋 수치 전달형이다.
- **논조 점검:** 둘 다 특정 설정의 수치다. 추측적 디코딩 이득은 모델·MTP 구성에 따라 달라진다.
- **다른 시각:** ①은 '필요한 토큰만 계산'의 정석 최적화이고, ②는 저메모리 환경의 반복 오버헤드 제거다. 영상 생성 서빙의 저VRAM 운용에 직접 도움이 된다.

**시사점:** MTP 추측 디코딩을 쓰는 배포는 입력 처리량 개선을 확인해 볼 수 있다. diffusion 오프로드 사용자는 사이클 시간 단축이 즉시 체감된다.

## 4. 그 밖의 배관 — vLLM KV 오프로드 access_mode, llama.cpp /models/sse 등

- **원문:** https://repojournal.com/showcase/local-llm (RepoJournal Local LLMs 와이어, 2026-11-23)
- **분야:** 엔진 · 종합
- **최초 게시:** RepoJournal 2026-11-23
- **시간 판정:** 정규 구간 내 확인

### 요약

하루치 소규모 변경들: vLLM 멀티티어 KV 오프로드 커넥터에 access_mode(read|write|readwrite) 추가 — CPU 캐시가 파일시스템에 쓰고 GDS가 그 파일시스템에서 GPU로 직접 읽는 구성이 가능해진다. llama.cpp 서버는 단일 모델 모드에서도 /models/sse로 다운로드·로딩 진행 이벤트를 제공한다. MLX는 윈도우 어텐션을 융합 CUDA 커널로 보낸다. vLLM의 OpenCUA·비디오 로더는 max_pixels·max_frames를 무시하지 않게 됐다. Ollama는 중복된 MoE 텐서 헬퍼를 mlxrunner/model로 옮겼다(동작 변경 없음).

### 논조·다른 시각

- **기사 논조:** 중립 — 배관(plumbing) 변경의 나열이다.
- **논조 점검:** '동작 변경 없음'은 작성자 주장이므로 의존 코드가 있으면 갱신 후 확인이 안전하다.
- **다른 시각:** KV 오프로드의 읽기/쓰기 분리는 스토리지 계층 설계의 자유도를 높인다. 대규모 배포에서 캐시 전략 선택지가 늘어난다.

**시사점:** 이날 Local LLMs 와이어는 총 115개 커밋·115개 PR·10개 릴리스를 집계했다. 개별 변경보다 빈도가 이 생태계의 속도를 보여준다.
