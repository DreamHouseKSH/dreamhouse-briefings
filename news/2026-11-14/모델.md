## 1. Perplexity, Decider v1.3 공개 — 생성이 아니라 확률로 답하는 결정 모델, Apache 2.0 가중치

- **원문:** https://www.perplexity.ai/hub/blog/perplexity-decider
- **분야:** 모델 · 오픈 가중치 / 분류 모델
- **날짜:** 공식 2026-11-12 (시각 미표시), MarkTechPost 11-13 보도
- **시간 판정:** 구간 경계 — 공식 날짜는 구간 직전, 구간 내 보도 확인

### 요약

Perplexity가 결정 모델(decision model) Decider v1.3과 더 작은 증류 모델 Decider Flash v1.3을 공개했다. 결정 모델은 문장을 생성하지 않고, 입력에 대한 예/아니오·다지선다·점수 질문의 답을 확률 분포로 반환한다. 한 번의 순전파로 같은 입력에 대한 여러 질문을 함께 처리해, 결과물 평가·요청 라우팅·유해 콘텐츠와 프롬프트 인젝션 탐지·검색 재순위화 같은 작업에 쓴다. 새 기능 Locate는 개체명 인식(NER, Named Entity Recognition — 텍스트에서 고유명사를 찾아 분류하는 작업), 개인정보 식별, 추출형 질의응답을 위해 선택된 텍스트 구간을 그대로 표시한다.

Decider v1.3은 Qwen3.8-27B 기반 27B, Flash는 Qwen3.5-4B 기반 4B 모델이다(Hugging Face 표기는 각각 26B·5B). 가중치는 Apache 2.0으로 Hugging Face에 공개됐고 OpenRouter와 Perplexity Decisions API에서도 쓸 수 있다. 회사 자체 평가에서 63개 질의 분류 작업 평균 정확도 91.6%, 답변 번복률 0.27%, 100만 건 처리에 26.47달러를 주장한다. 양자화 변형은 아직 없고 BF16 가중치 기준 약 49GiB(Flash 약 8.5GiB)의 GPU 메모리가 필요하다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 기능 설명과 자체 평가 중심의 출시다.
- **논조 점검:** 모든 성능 수치가 회사 자체 측정이며 독립 재현이 없다. MarkTechPost도 "모든 수치가 자체 보고"라고 지적했다. TypeSafe의 Jev 1.14와의 비교는 회사가 고른 평가다.
- **다른 시각:** MarkTechPost는 Flash가 금융·프로그래밍·법률에서 Jev 1.14에 뒤지고, Locate의 평균 점수(69.0)가 가장 낮다고 짚었다.

**시사점:** 생성 모델로 하던 분류·검열 작업을 저렴한 전용 모델로 옮기는 흐름이다. 로컬 배치는 자기 데이터 기준의 정확도·지연 시험 후에 결정하는 편이 맞다.

## 2. Zyphra, ZONOS3-Mini 공개 — 100M 활성 파라미터 MoE 음성합성, "첫 소리 80ms"

- **원문:** https://huggingface.co/blog/Zyphra/zonos3-mini
- **보도:** https://aiweekly.co/alerts/zyphra-open-sources-zonos3-mini-moe-tts-at-80ms-first-audio
- **분야:** 모델 · 오픈 가중치 / 음성 합성
- **날짜:** Hugging Face 릴리스 포스트 2026-11-12, AI Weekly 보도 11-13 11:00 UTC(11-13 20:00 KST)
- **시간 판정:** 정규 구간 내 보도 확인

### 요약

Zyphra가 오픈소스 TTS(Text-to-Speech, 텍스트를 음성으로 합성하는 기술) 모델 ZONOS3-Mini를 Apache 2.0으로 공개했다. 총 8억 개 파라미터 중 토큰당 1억 개만 쓰는 희소 MoE(Mixture-of-Experts, 전문가 조합 — 일부 하위 네트워크만 골라 계산하는 구조)이고, H100 112장으로 이틀 반 동안 학습했다고 밝혔다. 핵심은 15Hz의 새 오디오 코덱 ZAC-1이다. 회사는 같은 데이터 조건에서 DAC 기반 오픈 모델 대비 WER(Word Error Rate, 단어 오류율)이 10분의 1로 줄고 음색 유사도는 좋아졌다고 주장한다.

지연 수치도 회사 자체 측정이다. H100에서 첫 소리까지 중앙 80ms, Pixel 9 브라우저에서 570ms 미만, 43개 언어에서 실시간의 457배 처리량을 주장한다. 기술 보고서는 arXiv에 함께 공개됐다. 실제 한국어 품질과 장문 안정성은 직접 시험이 필요하다.

### 논조·다른 시각

- **기사 논조:** 긍정 — 회사 시연과 자체 수치 중심이다.
- **논조 점검:** WER 10배 개선 주장에는 "같은 데이터 조건"이라는 단서가 붙는다. 공개된 독립 벤치마크는 아직 없다.
- **다른 시각:** AI Weekly는 ElevenLabs·OpenAI TTS 같은 유료 음성 서비스 갱신 시점에 자체 호스팅 대안이 되는지 따져봐야 한다고 봤다.

**시사점:** 매일 음성 브리핑을 합성하는 작업 흐름에는 서브초 지연의 오픈 모델이 비용 구조를 바꿀 후보다. 실제 교체 판단은 한국어 품질 시험 후에 하는 편이 맞다.
