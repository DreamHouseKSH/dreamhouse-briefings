## 1. 마이크로소프트, 결정 모델 'Microsoft-Decision-1' 출시 — 입력 100만 토큰당 0.042달러, 출력은 무료

- **원문:** https://commandline.microsoft.com/microsoft-decision-1-model-foundry/
- **분야:** 모델 · 결정 모델
- **날짜:** 2026-10-09 (UTC, 한국 시각 10일 새벽)

### 미디어

![Microsoft-Decision-1 소개 카드 (Microsoft)](https://commandline.microsoft.com/wp-content/uploads/2026/10/introducing-microsoft-decision-1-our-model-for-fast-decision-making-card.png)

> 출처: 원문 페이지 (Microsoft Command Line 블로그) — 원본 이미지 링크(복제 저장 아님)

### 요약

마이크로소프트가 **결정 모델(decision model, 글을 생성하지 않고 정해진 선택지마다 확률을 매기는 모델)** **Microsoft-Decision-1**을 내놨습니다. 기업용 AI 개발 플랫폼 **Microsoft Foundry**와 여러 모델을 한 API로 묶어 파는 중개 서비스 **OpenRouter**에서 쓸 수 있습니다. 질문 유형은 예/아니오, 객관식, 점수 매기기이고, AI 답변이나 에이전트 행동을 기준표대로 채점하는 데도 쓸 수 있습니다. 쓰임새로는 요청 라우팅, 분류, 우선순위 정하기, 검증, 워크플로 제어를 꼽았습니다.

이 모델은 알리바바의 오픈 가중치 모델 **Qwen3.5-9B**를 바탕으로 마이크로소프트가 추가 학습(post-training)한 것이고, 앞으로 **MAI(Microsoft AI, 마이크로소프트 자체 AI 조직의 모델)** 와 OpenAI 모델로도 다시 만들 계획이라고 밝혔습니다. 회사 발표 기준으로, 학습에 쓰지 않은 약 15만 문항·36개 벤치마크 비교에서 정확도가 가장 높았고, 응답 속도는 2위 H2O-Lightning-4B v1.1보다 2.5배, GPT-6 Sol보다 35배 빨랐습니다(**P50 지연 시간**, 요청 절반이 이 시간 안에 끝나는 중간값 기준). 같은 요청을 8가지 방식으로 살짝 바꿔도 결정이 뒤집힌 비율은 평균 1.3%였다고 합니다.

내부 사례로는 Xbox 리서치가 1만 건 넘는 게임 피드백을 주제별로 분류하면서 GPT-6 Sol과 비슷한 품질에 14배 넘게 빠르고 200배 싸게 처리했고, Copilot 팀의 품질 측정에서는 GPT-5.6 Luna와 비슷한 수준에 100배 빨랐다고 소개했습니다. 가격은 입력 100만 토큰당 0.042달러이고 출력 토큰은 무료입니다(이 모델은 글을 출력하지 않기 때문입니다).

### 논조·다른 시각

- **기사 논조:** 긍정 — 회사 공식 블로그로, 'LLM과 다른 결정 모델을 모두 능가한다'는 자기 평가가 중심입니다.
- **논조 점검:** 모든 성능·속도·내부 사례 수치가 **회사 자체 측정**입니다. 벤치마크 대상과 방식을 회사가 골랐고, 글 끝에 'Jev의 정확도·보정 벤치마크를 추가했다'는 편집자 주가 붙어, 처음 공개 때는 이 분야 대표 경쟁 모델과의 비교가 빠져 있었음을 보여 줍니다.
- **다른 시각:**
  - 검증 부재 지적(OrcaRouter 블로그): Foundry 카탈로그의 벤치마크 탭에는 방법론 문단만 있고 숫자가 없다고 지적했습니다. 가중치는 배포되지 않아 내려받거나 직접 돌릴 수 없고, 보정(확률이 실제 적중률과 맞는지)이 얼마나 잘 됐는지 외부에 공개된 숫자가 없으니 '능력이 입증된 것'이 아니라 'API가 열린 것'으로 보고 자기 데이터로 먼저 시험하라고 권했습니다 ([OrcaRouter](https://www.orcarouter.ai/blog/microsoft-decision-1-ga-foundry-no-published-benchmarks)).
  - 데이터 상주 관점(Technspire): 유럽 고객에게는 출시 첫날부터 EU 데이터 존(데이터를 EU 안에서만 처리하는 배포 방식)을 같은 가격에 연 점이 가장 중요하다고 평가했습니다. 다만 기반 모델이 Qwen3.5-9B라는 점은 구매 시 기록해 둘 사항으로 꼽았습니다 ([Technspire](https://technspire.com/en/blog/microsoft-decision-1-foundry-0-042-eu-data-zone-decision-models)).

**시사점:** 결정 모델이 스타트업 실험에서 빅테크 정식 제품군으로 올라왔습니다. 에이전트 비용을 줄이는 '싸고 빠른 판단 계층'이 표준 부품이 되는 흐름입니다.

## 2. Nace AI, 9B 결정 모델 'Drex 1.5' 오픈소스 공개 — 닫힌 모델 Jev와 동급 점수

- **원문:** https://www.marktechpost.com/2026/10/09/nace-ai-open-sources-drex-1-5-a-9b-decision-model-that-scores-options-not-text/
- **분야:** 모델 · 결정 모델/오픈 가중치
- **날짜:** 2026-10-09

### 미디어

![Drex 1.5 소개 배너 (MarkTechPost)](https://www.marktechpost.com/wp-content/uploads/2026/10/WP-BLOG-BANNER-4-1-1-1024x768.png)

> 출처: 원문 페이지 (MarkTechPost) — 원본 이미지 링크(복제 저장 아님)

### 요약

**Nace AI**가 89억 5천만 개 파라미터(8.95B, 모델 크기)의 결정 모델 **Drex 1.5**를 공개했습니다. 텍스트를 쓰지 않고, 상태(텍스트나 **JSON**(JavaScript Object Notation, 데이터를 주고받는 표준 텍스트 형식))와 질문을 받아 사용자가 준 선택지마다 확률을 한 번의 계산(single forward pass)으로 돌려줍니다. 질문 유형은 객관식, 예/아니오, 순서 점수 세 가지입니다. TypeSafe의 Jev와 같은 `POST /v1/systemone` 요청 형식을 써서, 기존 Jev 사용 코드는 환경 변수 몇 개만 바꾸면 그대로 돌아간다고 회사는 설명합니다.

공개 벤치마크인 Decision Index 0.3.1(37개 벤치마크)에서 58.08점으로, 닫힌 모델 Jev 1.13.0(57.96점)과 리더보드의 '동점 범위' 안에 들었고 10B 미만 모델 중 최고점이라고 합니다. 다만 이 점수는 Nace가 공식 도구로 직접 돌린 결과입니다. 긴 문서에 강해 3만 2천~12만 8천 토큰 문서에서 93.4% 정확도를 냈지만, 일반 지식 시험인 GPQA Diamond에서는 45.4%로 Jev(78.6%)에 크게 뒤졌고 세밀한 감성 분석(ACOS)에서도 7.4%로 약했습니다.

실행 방법은 네 가지입니다. CUDA GPU 1장에서 돌리는 파이썬 런타임, Nace가 고친 llama.cpp 포크(BF16 또는 약 9.5GB짜리 Q8_0 **GGUF**(GPT-Generated Unified Format, llama.cpp 계열에서 쓰는 모델 파일 형식) — 애플 실리콘·CPU에서도 동작), Nace의 Ollama 포크, 그리고 OpenRouter 호스팅(입력 100만 토큰당 0.04달러, 출력 0달러)입니다. 라이선스는 사용 제한 조항이 있는 **RAIL-M(Responsible AI License — Model, 특정 용도를 금지하는 책임 있는 AI 모델 라이선스)** 입니다.

### 논조·다른 시각

- **기사 논조:** 긍정 — '닫힌 모델과 1장짜리 GPU로 맞먹는다'를 핵심으로 내세우되, 약점(GPQA·감성 분석)과 제한 사항도 따로 정리했습니다.
- **논조 점검:** 벤치마크 점수는 **회사가 직접 돌린 결과**를 옮긴 것입니다. 기사 스스로 Nace가 벤치마크의 학습용 분할로 학습했다고 밝히고 있어, 처음 보는 분야에서는 결과가 다를 수 있습니다. 회사 출시 차트는 예전 버전(0.2.1) 점수를 써서 숫자가 조금 다릅니다. 로컬 실행에는 공식 llama.cpp·Ollama가 아니라 Nace의 포크가 필요하다는 점도 기사에 적혀 있습니다.
- **다른 시각:**
  - 찾은 반론 없음 (검색 범위: 웹 검색 'Nace AI Drex 1.5 open source decision model' 결과 — Hugging Face 모델 카드·Drex 문서·MarkTechPost. 출시 직후라 독립 평가나 비판적 리뷰는 아직 찾지 못함).
  - 예상 쟁점: 같은 분야 경쟁 모델(Jev·Decision-1)과 비교하는 공개 리더보드가 주로 업계 스스로 만든 것이라, 독립적인 평가가 나오기 전까지는 점수 차이를 크게 해석하기 어렵다는 지적이 나올 수 있습니다.

**시사점:** 결정 모델 분야에도 '닫힌 모델을 따라잡는 오픈 가중치' 구도가 생겼습니다. 사내에서 데이터를 밖으로 보내지 않고 분류·라우팅을 돌리고 싶은 팀에겐 시험해 볼 만한 선택지입니다.

## 3. 알리바바 Qwen-Image-2.1-Turbo 공개 — 40단계 걸리던 이미지 생성을 8단계로

- **원문:** https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo
- **분야:** 모델 · 이미지 생성/오픈 가중치
- **날짜:** 2026-10-09

### 미디어

![Qwen-Image-2.1-Turbo Hugging Face 썸네일](https://cdn-thumbnails.huggingface.co/social-thumbnails/models/Qwen/Qwen-Image-2.1-Turbo.png)

> 출처: Hugging Face 모델 페이지 — 원본 이미지 링크(복제 저장 아님)

### 요약

알리바바 Qwen 팀이 이미지 생성·편집 모델 **Qwen-Image-2.1**의 가속판 **Qwen-Image-2.1-Turbo**를 9일 Hugging Face에 올렸습니다. 같은 70억 파라미터(7B) 구조를 그대로 쓰면서 **디노이징(denoising, 잡음에서 시작해 조금씩 그림을 다듬는 생성 과정)** 단계를 기본 모델 예제의 40단계에서 8단계로 줄인 체크포인트입니다. 이미지 라이브러리 **Diffusers**의 `QwenImage21Pipeline`으로 불러 쓰고, 2048×2048 정사각형을 포함한 7가지 해상도를 지원합니다.

추천 8단계 샘플링 일정이 체크포인트 안에 저장돼 있어 자동으로 적용됩니다. 그래서 단계 수(num_inference_steps)만 바꿔서는 일정이 바뀌지 않고, sigmas 값을 직접 넘겨야만 덮어쓸 수 있습니다. 기본값으로 **CFG(Classifier-Free Guidance, 프롬프트를 얼마나 강하게 따를지 조절하는 추가 계산)** 는 1이라 추가 계산을 하지 않고, 텍스트·참조 이미지 정보를 단계마다 재사용하는 **KV 캐시(Key-Value cache, 앞서 계산한 결과를 저장해 다시 쓰는 기법)** 도 씁니다.

같은 날 Qwen-Image-2.1 Pro와 Turbo **API(Application Programming Interface, 프로그램끼리 기능을 주고받는 창구)** 도 알리바바 클라우드 Model Studio에서 정식으로 열렸습니다. 라이선스는 기본 모델과 같은 **Qwen Research License**로, 상업적으로 쓰려면 별도 허가가 필요합니다.

### 논조·다른 시각

- **기사 논조:** 중립 — 원문은 Hugging Face 모델 카드라 사용법과 사양 위주입니다.
- **논조 점검:** 회사가 올린 1차 자료로, Turbo 체크포인트 자체의 품질·속도·메모리 수치는 **하나도 공개되지 않았습니다**. 쇼케이스 이미지는 회사가 고른 결과물입니다. '8단계'는 단계 수일 뿐 실제 걸리는 시간은 아닙니다.
- **다른 시각:**
  - 재현 함정과 라이선스(OrcaRouter 블로그): 진짜 변화는 단계 수가 아니라 샘플링 일정이 가중치 안으로 들어간 점이라며, 기본 모델 예제 코드를 그대로 Turbo에 쓰면 오류 없이 돌지만 쇼케이스와 같은 결과가 나오지 않을 수 있다고 경고했습니다. 아직 정식 출시되지 않은 Diffusers 소스 버전이 필요하고, 비상업 연구용 라이선스는 빨라졌다고 바뀌지 않으니 제품에 넣으려면 라이선스부터 확인하라고 했습니다 ([OrcaRouter](https://www.orcarouter.ai/blog/qwen-image-2-1-turbo-release)).
  - 중국 AI 동향 매체(AIGC.NEWS): 성능 주장은 '회사 발표이며 아직 독립 평가 없음'으로 분류하고, 해외 개발자는 상업적 사용 제한을 검토해야 한다고 짚었습니다 ([AIGC.NEWS](https://aigc.news/events/qwen-released-qwen-image-2-1-turbo-on-hugging-face-2026-10-09-4fa999ac/)).

**시사점:** 오픈 이미지 모델 경쟁이 '품질'에서 '속도·비용'으로 옮겨 가고 있습니다. 다만 상업용으로 쓰기엔 라이선스 제약이 그대로라, 개인·연구용 로컬 생성에 먼저 의미가 있는 소식입니다.
